# 觀護人學習平台｜Probation Study Desk

> 以臺灣司法特考三等觀護人為核心的開源自主學習網站。結合考古題與申論練習、共同科目、學習紀錄、少年司法研究及 AI 輔助訂正，協助學習者把「讀過」轉化為「寫得出來」。

本專案由個人自主開發、維護，**並非考選部、司法院或其他政府機關的官方網站**。網站提供的是學習輔助與參考回饋，不代表正式國家考試閱卷結果。

## 專案理念

國家考試的準備，不只是累積閱讀時數，更需要反覆完成「辨識爭點 → 建立架構 → 書寫論證 → 檢討訂正 → 間隔複習」。本網站希望把這個循環整合在一個適合電腦與手機使用的學習環境。

主要設計原則：

1. **先作答，再看參考內容**：強調自主回憶、申論架構、法條與理論的實際運用。
2. **以歷屆題目為學習起點**：保留年度、科目與題源標示；改編題與原題清楚區分。
3. **逐步改善答案品質**：透過自評、AI 批改提示詞、弱點記錄與再次作答，追蹤自己的進步。
4. **重視少年司法的法源與實務**：關注《少年事件處理法》、相關程序保障、兒童權利公約（CRC）與少年處遇實務。
5. **個人學習資料由使用者掌握**：以瀏覽器本機紀錄與手動 JSON 備份為主，不要求註冊網站帳號。

### 函授學習管理

- [**函授學習管理**](lectures/)：建立函授堂次、逐堂記錄觀看分鐘與剩餘時數，依每日可用時間與既有練習預留時段，**預覽7／30／60／90天課表與月曆**，確認後才更新，落後時可重新計算。可使用「依序完課、每日輪替一科、依科目權重分配、固定星期科目」四種排課方式，並可自訂考科名稱及停排特定科目。
- 函授課程為**使用者自行登錄**，網站不讀取函授業者帳號、影片或購買資訊；無需付費 AI、無後端帳號同步。跨裝置請使用[完整 JSON 備份中心](backup/)。
- 本功能與既有每日30分鐘訓練、七科學習診斷、申論及題庫各自保存；函授排程不會修改現有練習資料。

### AI 在本站扮演的角色

本站的「一鍵複製 AI 批改」是**提示詞工作流**：複製題幹、個人答案與批改規則，使用者自行貼到 ChatGPT 等工具取得回饋，再把評語貼回本站保存。這**不是本站直接呼叫 AI API 的自動閱卷**，也不代表 AI 回答已完成法規或實務見解查核。對外貼送內容前，請自行刪除敏感資料。

**自訂 AI 批改提示詞（2026-10-22）**：在「考古題練習臺」、「專業科目練習」、「每日 30 分鐘練習」及「晚間學習室」的一鍵批改按鈕上方，展開「自訂 AI 批改提示詞」。選擇批改模式（完整申論／答題方向）及適用考科，輸入個人規則並按「儲存此組合」，後續複製提示詞時會自動加上該規則。單一考科沒有設定時會沿用「全部考科」的同模式通用規則；兩個批改模式互不干擾。未自訂時維持原有提示詞。

- 「恢復預設」只清除目前模式／考科的專屬設定；如果存在「全部考科」通用規則，仍會繼承它。若要完全取消自訂，請將同模式的通用規則也恢復預設。
- 可從同一設定區「匯出設定 JSON」或「匯入設定 JSON」。匯入前先檢查內容與大小，遇到同一模式與考科時採匯入版本，其餘原設定不刪除。
- 提示詞設定另存於目前網站來源的瀏覽器 localStorage（鍵名 `psd-ai-custom-rules-v1`），**已納入完整學習紀錄 JSON 備份**，也可從設定區獨立匯出。GitHub Pages 與 Cloudflare 以及不同裝置之間，不會自動同步。
- 個人規則可以調整批改重點與回饋格式，但網站仍保留原題、題源欄位及實際作答；答題方向模式仍不以全文完整度給百分制分數。不要在自訂規則寫入個資、API 金鑰或公務秘密。

## 如何使用

建議採取一個可持續重複的學習循環：

1. **選題**：依考科、年度、主題或自身弱點選擇一題。
2. **限時作答**：利用 30 分鐘練習或自由練習；先填寫「爭點、依據、涵攝、結論」四格草稿，再完成申論。
3. **獨立核對**：作答後檢查參考架構、法條、學理、題目要求與缺漏的設問。
4. **取得補充回饋**：有需要時複製 AI 批改提示詞至外部工具，將回饋貼回原題；對法律結論仍應自行查證。
5. **訂正與回練**：記錄不足之處、標記待複習，過幾日再以相同題目重新作答。
6. **保存紀錄**：定期從對應模組或完整備份中心匯出 JSON；重要申論可另外列印／另存 PDF。

閱讀少年司法週報時，建議先查閱原始官方文件，再使用本站的制度分析與複習提示延伸思考。

## 資料保存與隱私

本站主要在**目前瀏覽器的本機儲存空間**保存作答、草稿、收藏、自評及部分閱讀進度；網站不提供跨裝置自動帳號同步。

- 同一人使用不同裝置、不同瀏覽器、無痕模式，**不會自動共享答案**。
- GitHub Pages 與 Cloudflare 即使展示相同頁面，仍屬**不同網站來源（origin）**；兩邊的本機紀錄不會自行合併。
- 建議定期備份：在 [備份中心](backup/) 匯出 JSON，實際確認檔案已下載，再自行存放於私人雲端硬碟或其他安全位置；換裝置後由本人手動匯入。
- 如有同題或同日期的不同答案版本，先檢查匯入預覽及衝突資料，不要直接覆蓋唯一原稿。
- 清除瀏覽器網站資料、裝置損壞、儲存空間限制或 Safari 清理機制，都可能導致紀錄遺失。
- **請勿輸入真實少年事件的可識別個資、機密卷證、公務秘密、密碼或憑證；也不要將私人 JSON 備份張貼到公開 Issues、PR 或儲存庫。**

完整 JSON 備份僅能讀取目前網站來源中指定的紀錄。部分即時計時資訊使用 `sessionStorage`，不一定包含在跨分頁備份裡；匯入時仍須閱讀頁面顯示的限制。

### 離線模式的差異

| 使用模式 | 前提與限制 |
| --- | --- |
| **GitHub Pages／Cloudflare（HTTPS）** | 可在支援的瀏覽器預先下載 PWA 離線快照；快照可能落後於最新題庫；AI 與外部網站仍需連線 |
| **GitHub 原始碼 ZIP（`file://`）** | 從 GitHub `Code → Download ZIP` 下載 `main`、解壓，雙擊根目錄 `index.html`；需保留原資料夾結構與 `file-data/` 等產生檔 |

瀏覽器對 `file://` 網頁的本機儲存及跨頁共用**沒有一致保證**。ZIP 模式下特別建議每次重要作答後自行匯出 JSON；少年司法週報以本機相容閱讀方式開啟，與線上 React 版並非完全相同介面。下載的法規與研究資料亦不會自動更新。

## 技術架構與檔案結構

本專案以**靜態網站、前端儲存與多模組整合**為基礎，無須自建帳號資料庫即可使用主要學習功能。

| 層次 | 技術／做法 |
| --- | --- |
| 多數學習頁面 | HTML、CSS、JavaScript，直接讀取題庫 JS／JSON |
| 少年司法週報 | React、TypeScript、Vite；發布編譯後的靜態資源 |
| 使用者紀錄 | 瀏覽器 `localStorage`／部分 `sessionStorage`、手動 JSON 匯出匯入 |
| 離線學習 | Service Worker、Cache Storage、PWA 靜態資源快照；ZIP 的 `file://` 相容資料橋接 |
| 原始碼與正式版本 | GitHub `main` 為整合程式來源；GitHub Pages 提供主要公開入口 |
| Cloudflare | 另有部署及版本驗證流程；是否已切換特定 production 網址，依實際部署狀態及驗收紀錄為準 |
| 內容同步 | 部分閱讀資料與每日題由維護者的 Google Apps Script／GitHub 流程寫入公開 JSON；不是使用者瀏覽器直接連結私人 Drive |

`upload/`、測試資料及各版本相容檔可能同時存在於專案中，**不要僅憑資料夾名稱判斷可刪除**；移除前應檢查線上引用、原題 ID、作答格式與離線快取。

## 本機執行與自行部署

### 一般使用者

直接開啟[正式網站](https://leokychen.github.io/probation-study-desk/)即可使用，無須安裝套件。若要保留離線版本，可先依網站的「離線閱讀與作答」指示下載資源，或下載 GitHub 原始碼 ZIP；兩種方式的資料保存限制不同，請參照前節。

### 開發者

複製專案：

```bash
git clone https://github.com/LeoKYChen/probation-study-desk.git
cd probation-study-desk
```

專案根目錄的 `package.json` 使用 **Node.js 22.13.0 以上**、Vite、React 與 TypeScript，主要供 React 週報介面等前端開發使用：

```bash
npm install
npm run dev       # Vite 開發預覽
npm run check     # TypeScript 檢查
npm run build     # Vite 建置
```

**注意：** `npm run build` 不會自動重建整個多模組網站。大部分作答頁面本來就是靜態 HTML／JavaScript，必須連同相對路徑、JSON、圖片及 PWA 資源一起發布；不可只上傳 Vite 的輸出資料夾就認為全站已完成部署。少年司法週報另可依 `juvenile-news/README.md` 與 `juvenile-news/source/` 維護。

自行 Fork／部署時，應調整自己站點的絕對網址及路徑，重新檢查 Pages 發布設定與授權內容。同步用的 GitHub Token、Google Apps Script 屬性及私人 Drive 資料夾不會隨 Fork 自動移轉，也不應寫入公開程式碼。

## 資料維護與品質控管

### 資料來源與單一正本

- 考古題、每日題與週報的正式資料各有對應 JS／JSON 檔案；應維持**題目 ID 穩定**，避免既有作答無法對應。
- `daily-simulation/questions.json` 是每日模擬題正本；`daily-simulation/documents.json` 是公開閱讀文件資料。
- `juvenile-news/issues.json` 是已發布的少年司法週報資料。
- `common-subjects/` 的題目與來源標示應保留個別模組的授權及改編資訊。
- `file-data/*.generated.js` 是由原始 JSON 自動產出的 ZIP 相容檔，不應手動修改成與正本不一致的第二套題庫。

### 建議的內容檢查

1. **題源真實性**：確認年度、考試類科、科目及題次；原題、改編題、自編題分別標示，查不到原卷時不得宣稱已核對。
2. **法源有效性**：優先核對[全國法規資料庫](https://law.moj.gov.tw/)的現行法、施行日期及相關修法；歷年考古題應視題意辨明適用的法律時點。
3. **實務與學理**：不得捏造判決、釋憲文號、函釋、研究或引文；存在爭議時應標示不同見解。
4. **申論品質**：檢查設問完整性、爭點、規範與理論、事實涵攝、結論以及配分合理性；通過品質驗收與單純可顯示參考答案應分開標示。
5. **回歸驗證**：更新資料後檢查題數、ID 唯一性、備份相容、手機介面、離線快照及不清除舊紀錄等條件。

部分可用的開發檢查指令（依對應模組及工作流程執行）：

```bash
node common-subjects/test-v02.cjs
node backup/test.cjs
node print/test.cjs
node scripts/generate-file-data.cjs --check
```

GitHub Actions 的通過狀態表示相應程式檢查或自動化測試通過，**不等於每題已完成法律正確性、學術內容或國考閱卷標準的人工驗收**。部署紀錄與階段性測試參見 [`docs/`](docs/) 及 [GitHub Actions](https://github.com/LeoKYChen/probation-study-desk/actions)。

## 備考書桌本機版

`study-desk/` 提供獨立的作答、版本、多AI評語、訂正、再次回想與Markdown筆記流程，使用IndexedDB持久保存。目前採本機保存與JSON手動備份，不需帳號、Supabase或token；跨裝置自動同步依使用者最新指示暫緩。

首頁側欄提供備考書桌入口。舊模組透過明確匯入保存快照，不會自動同步各舊頁面的後續編輯，也不會自動寫回舊模組。書桌支援函授主題對應、自訂複習間隔、推薦理由、舊筆記接續及確認後清除紀錄；選題不列社會工作、國文、法學知識與英文。跨裝置請手動匯出／匯入JSON，測試站資料不會自動移至正式站。參見 [開發說明](study-desk/README.md) 與 [雲端接入說明](cloud-sync/README.md)。

### 第二階段：申論答案與雙 AI 工作臺雙向交接（2026-10-22）

「每日模擬題／晚間學習室」以及「備考書桌」新增「送交雙 AI 交叉審查」。使用者確認後，兩個頁面以受限的 `postMessage` 交換題目及本次答案，不透過 URL 參數傳答案。工作臺完成兩家 AI 獨立分析、交叉評論及修訂後，可再由使用者按鈕回傳，並在來源頁二次確認。每日模擬題只附加至既有 `aiFeedback`；備考書桌只附加一份與原作答版本綁定的「待查證」回饋。其他題庫、作答版本、複習排程與已保存評語維持不變。
