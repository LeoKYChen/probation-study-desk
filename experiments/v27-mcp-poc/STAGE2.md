# v2.7 × MCP｜第 2 階段行政函釋驗收

**範圍：原本 v2.7 收錄的 21 筆法務部系統行政函釋索引**。本階段只核對資料，不改寫原索引，不把舊函釋當成現行法。

## 你可以怎麼理解這個測試？

原本 v2.7 的 21 筆資料，像是 21 張「函釋書籤」，有日期、文號和官方網址，但沒有在站內保存原文。這次讓 MCP 逐張書籤開啟函釋，再另外讀取官方網頁，確認 MCP 沒有讀錯。

一、每筆直接以 `moj:FE...` 呼叫 `get_agency_interpretation`，核對：

- 文件識別碼、發文字號、日期、發文機關。
- 來源必須是 `mojlaw.moj.gov.tw` 的相同文件。
- 官方是否有「廢」標示；有標示時 MCP 必須回報「停止適用」。
- 沒有「廢」標示時 **不能**宣稱仍有效，應當是「效力待核對」。
- 從官方原始 HTML 和 MCP 分別擷取的函文內容能否一致。輸出只記錄 SHA-256 比對資訊、診斷及網址，**不把21件原文寫進公開 GitHub 或測試產物**。

二、另外抽 5 筆，用文號呼叫 `search_agency_interpretations`，測試搜尋是否可以找回正確的文件；這與直接依 ID 取得原文是兩種不同能力。

## 狀態怎麼判讀？

- `passed`：MCP 取得文件，官方頁面可讀，識別碼、文號、日期、機關、全文及效力標示核對無誤。
- `review`：因網站連線、欄位缺漏、全文格式差異等因素無法確認，尚不得判定正確或錯誤。
- `failed`：確定與官方資料矛盾，例如文號錯配、日期錯配、錯誤有效性標示。這種情況要修正後再重驗。

## 階段驗收基準

- 21 筆逐一核對，另有 5 筆文號檢索測試。
- 以 **至少 19/21 筆完整核對成功**作為初步候選門檻；即使達標，未核對的資料仍不能標示完成。
- 正式整合門檻更嚴格：21/21 筆均完成來源與內容核對、沒有錯誤引用／效力宣稱，5 個指定文號查詢均可找到對應 ID。
- 研究用的「是否仍具現行效力」應另查後續函釋與法規修正；本測試只驗證**官方頁面目前有沒有停止適用的標籤**，不判定實質法律效力。
- 連線失敗不可認定官方文件不存在；對外也不得聲稱覆蓋法務部全量函釋。

## 技術保護

- 獨立分支 `experiment/v27-mcp-stage2`，不修改 `development/v2.7/`、v2.5、Cloudflare 或主分支。
- 固定第三方 MCP 版本 `ef677ad63c3206fc211a083fad8b1d9ef5015222`。
- GitHub Actions 只有 `contents: read`；不讀取 Secrets，不下載少年裁判、不上傳函文全文。
- GitHub Actions 最終綠勾只代表沒有確定性錯誤及執行完成，必須再檢查 artifact 的 `stage2_accepted` 才能判斷階段是否驗收通過。

本階段若發現個別文號、日期或函釋分類與官方不符，先保留原網站資料，列出差異及正確來源，待審查後才提出修正。
