# Stage 3r｜法規與函釋來源分級介面（合成資料）

這是 **獨立離線示範頁**，不是正式 v2.7，也沒有新增 PDF 轉存功能。

## 使用

直接在瀏覽器打開 `index.html` 即可切換「全部資料／法規版本／行政函釋」。請把 `index.html`、`model.js`、`app.js`、`style.css` 放在同一資料夾。部分瀏覽器對 `file://` 的 CSP 與外部腳本有不同處理；若本機不能載入，可在此資料夾使用 `python -m http.server 8765 --bind 127.0.0.1`，再瀏覽 `http://127.0.0.1:8765/`。本頁無對外網路 API 呼叫，伺服器僅限本機連線。

測試（Node 24，免安裝套件）：

```bash
node --test model.test.cjs
```

## 這個原型刻意**不做**的事

- 不顯示真實法規、21 件函釋或任何個案內容；五筆資料均以 `TEST_*_SYNTHETIC_...` 造假。
- 不將歷史法規快照、修正公布日推定為現行條文或施行日。
- 不把四件僅官方要旨的函釋補寫成全文；也不把本站整理摘要假冒官方要旨。
- 不提供任何個別司法裁判查詢、PDF 轉存、上傳或下載。
- 不連線官方資料庫、不儲存 API 帳密、不使用 Cloudflare、不合併主分支。
- 不把「來源抽樣通過」變更為「整個 v2.7 已驗收及獲准部署」。

## 歷史來源分級依據

- [Stage 1 法規驗收](../STAGE1_ACCEPTANCE.md)：20/20 指定樣本，但不是全庫現行法驗證。
- [Stage 2 函釋驗收](../STAGE2_ACCEPTANCE.md)：21 筆 metadata、17 官方全文、4 僅官方要旨；效力未驗。
- [Stage 3q 上線阻擋](../STAGE3Q_RESULT.md)：仍須個別審查、正式來源更新、敏感資訊處理與使用者同意才能考慮整合。

## 正式整合前的必要條件

下一步須**另外**設計可信的法規版本來源、個別施行條款審查，並以實際來源 ID 關聯各件函釋的官方全文／要旨程度。畫面上的合成 `contentLevel` 值不能直接變成可信的後端認證；須獨立官方來源查核與版本紀錄，並在 UI 清楚標示「最後核對時間」及函釋現行適用效力尚待確認。
