# v2.7 × MCP 第 3 階段｜第一輪：公開司法資料來源可用性試驗

## 為何先做小規模試驗？

前兩階段（法規、行政函釋）已有官方資料與既有索引可對照；但司法院裁判書的取得方式、官方網頁防護、歷審、撤除，以及立法院資料的呈現方式不同。若未經測試便開始大量下載或轉存，會增加來源錯配及公開限制風險。

本輪先做以下 **9 個檢查**：

| 編號 | 數量 | 測試內容 |
| --- | ---: | --- |
| C01–C03 | 3 | 已公布的憲法裁判／解釋：釋字 748、釋字 803、111年憲判字第1號，檢查 MCP 回傳及官方頁面基本可回查性 |
| L01–L02 | 2 | 《少年事件處理法》第3條之1、《保安處分執行法》第74條之2，是否能查到立法院法條沿革及理由 |
| N01 | 1 | 查不存在的「釋字第9999號」：應回報查無資料，不能捏造 |
| J01–J03 | 3 | 對公開的最高法院成人刑事類議題搜尋各取一筆候選裁判，嘗試取得公開全文與來源連結 |

注意：J01–J03 的「候選裁判」由實際司法院搜尋結果動態產生，不預先虛構案號；本輪不得搜尋受保護的少年案件。不論公開網頁有無個人資訊，**不把裁判原文、當事人姓名、案情、摘要或全文衍生資料寫入 GitHub / Actions 成果檔**，僅保留公開 JID、官方查詢連結、欄位存在性、錯誤原因及文長等測試資訊。

## 分級判定

- **passed**：通過本輪已定義的最小來源真實性檢查（例如官方網頁可回查，識別碼一致）。不是法院實體見解正確性驗收。
- **review**：被官方網站擋住、全文及歷審資料尚未交叉核對、只有 MCP 快取、立法理由尚未回到相對應的官方原件等；均不能冒充正式驗收通過。
- **failed**：證實識別碼錯配、來源網址非官方、無效裁判卻被工具回覆存在等。

## 完整第 3 階段驗收所需條件（不是第一輪）

1. **10 件**事先確認公開、具有可核對官方來源的不同裁判：逐件驗案號、法院、裁判日期、公開狀態；能取得全文的部分比對原文。官方不開放／遭撤除者不得被當成正常全文儲存。
2. 歷審資訊須標示完整性；缺資料不得推定沒有上訴。案件遭撤除的資料存取及衍生索引清理能力另作安全驗證。
3. 至少 **5 件**憲法裁判或立法資料案例，對官方原件或可讀全文獨立查核，保留來源、發布日期；不得只驗證 HTTP 200 就算全文正確。
4. 搜尋不得回傳已知虛構案號，不能把少年保護事件未公開裁判納入。
5. 第 3 階段的最終驗收文件須逐項列出 **passed／review／failed**，不能用 GitHub 綠勾取代資料正確性。

**第一輪不會修改** `development/v2.7/`、`services/v2.7-judgment/`、Cloudflare、GitHub 正式分支；不會啟用司法院 API 登入或使用 Secrets，也不會部署公開的裁判檢索服務。

## 與第 2 階段 B 方案的關係

使用者 2026-10-15 已選 B 方案：21 件函釋依官方公開程度完成「17 全文／4 官方要旨」分層核對；目前只允許進入本測試階段，不准聲稱 21 件全文已完成審核，也不代表已取得函釋現行適用性的法律結論。
