## 二、查核的原始官方依據

1. [司法院裁判書開放 API 規格說明（114.08.22 版）](https://opendata.judicial.gov.tw/api/Newses/42/file)，第 1、3、5–6 頁：Auth、JList、JDoc、JFULLTYPE、JFULLCONTENT、JFULLPDF、ATTACHMENTS，以及異動／撤除的處理方式。
2. [司法院開放資料使用規範](https://www.judicial.gov.tw/tw/communique/dl-115081-23e72637eb1d41f7b7606d097f3f0a52.html)，第 1–2 頁：一般與會員開放資料、無償加值授權、取用方式、來源標示、資料正確性、異動及第三人權益。
3. [司法院裁判書系統說明](https://judgment.judicial.gov.tw/readme.aspx)：網站提供「轉存 PDF」產製含頁行號的版本，且網站資料與判決原本不一致時，仍以判決原本為準。

**法律解釋注意：** 平臺開放資料之加值使用本身原則上無償且不當然另需書面許可，但應符合資料類型及取得規範；不能把會員資格／使用條款／個資／異動義務省略。至於本輪十三項額外准入條件及八類副本盤點，屬**專案為降低上線風險而訂的工程建議**，並非全部出自官方規範逐項明文要求。

## 四、十三項準備門檻與八類資料副本

本輪的 **13 項準備審查**，涉及：
- 會員及最新規範；
- 專案管理者對單件實際測試的明確同意；
- 官方身分、當下公開性；
- 可確認與來源同版的可信獨立文字／畫面參考；
- 司法／個人資料使用適當性；
- PDF 沙箱與憑證安全；
- 原件／快取／索引／衍生文字／CDN／匯出／備份／日誌的生命週期及撤除驗證。

**13 項全部勾選也仍然不可啟用真實 API：** `paper_requirements_only_real_evidence_still_required` 只表示「模擬輸入的待辦欄位已填齊」，沒有實際核對帳號身分、司法來源、更新或撤除能力。所有結果繼續保持 `permissionToFetchPdf=false`、`allowMergeOrDeployment=false`。

更新與撤除均另外用合成測試覆蓋：

- **同 JID 更新：** 應停止舊版輸出、失效快取與衍生資料，直到同版新原文重新驗證；本輪不對真實資料做此動作。
- **正式撤除：** 應停止顯示個案資訊並處理已取得內容。即使模擬八個副本全部回覆「清除」，程式依然將 `actualPurgeProven=false`、`caseCanBeServedAgain=false`。
- **HTTP 403／404／逾時：** 不自行推論「司法機關已撤除」，但將當下可用性列為未知、禁止舊版本當成可靠現況繼續輸出。
- **備份／日誌：** 真正的刪除、依法保存例外、保留期限及到期銷毀機制，須進一步完成個資及紀錄保存政策審查。合成副本狀態不等於真實備份已刪除。

## 七、實際可執行的下一步

**不建議再單純增加更多合成 PDF 測試。** 第 3 階段的主要阻擋目前在**權威取用與持續公開狀態**，不是本地 PDF 解析功能。接下來應優先：

1. 檢視實際要營運的公開 v2.7 網站是否**一定需要保存／展示裁判 PDF**；若不是，採**只提供司法院通用查詢入口**，PDF 永遠標明本站未驗證，最省成本與後續撤除風險。
2. 若確需正式 PDF 功能，由專案管理者**另行**確認要不要申請司法院資料開放平臺會員、在適當安全環境保管憑證、完成個資與存取政策審查；**切勿在聊天、GitHub 或公開環境提供帳密或 Token**。
3. 取得合法官方 API 機制及獨立參考來源、後端隔離、撤除同步與副本控制證據後，再**另經明確同意**做極小量公開成人文書的真實 PDF 取用試辦。未滿足條件前均維持 No-Go。
