## 二、執行及驗收規範

- 最多 6 件官方 `FJUD/data.aspx` GET，僅根據公開 JID 取得對應網頁；不先跑關鍵字搜尋，不碰原先完成的十件樣本。
- 每件需先由官網的結構化中繼資料確認**法院、案號、裁判日期及民事案件類型**。
- 官方正文需達 **10,000 正規化字元**、有實質 `.htmlcontent`／`.text-pre` 等正文區塊，才可觸發下一步的 MCP 全文對照；未達者明確列 `review`。
- MCP 最多 3 次取得，且固定上游 `ef677ad63c3206fc211a083fad8b1d9ef5015222`。採官網 `#jud` 全容器或獨立正文區塊與 MCP 正規化全文**完全一致**的嚴格判定；抽樣片段高重疊不足以通過。
- 一件長篇一致即可認定最低目標「長篇文字忠實性驗證成功」，兩件則另記「不同樣本重現」；未取得合格案例不能降低 10,000 字元標準。
- 每件個案只能驗證**當次取得的官方文字及身份資料**；不推論未來仍公開、裁判已確定或已完成撤除合規。

## 三、PDF 的最低安全驗收規格（這輪只訂條件，不下載實際司法 PDF）

單有 PDF URL、HTML 預覽、OCR 產出的片段或 HTTP 200 不能認定全文完整。將來實際支援 PDF 的可接受證據至少包括：

1. **來源及權限：** 僅官方核准的 HTTPS 來源、明確合法使用方式與有效公開狀態；不假冒登入、不繞過反機器人保護；不能把需會員授權的 `JFile` 當成可任意直接下載。
2. **檔案完整性：** 在安全容量限制內確認實際 PDF bytes，PDF 語法及頁碼、頁數一致性；排除只收到登入頁、錯誤頁或部分檔案。雜湊與檔案本身只能在受控短暫記憶體內使用，避免在公開 Repo 或日誌留下敏感資料。
3. **案件識別：** 獨立比較官方中繼資料／裁判日期與 PDF 首頁案號及法院；有任何不明或不同應中止並保留 `review`。
4. **逐頁擷取：** 每一頁都能成功抽取有意義的內文，並可檢測空白頁、掃描圖片頁、亂碼、漏頁與頁碼垃圾；需要 OCR 時應另行驗證辨識品質，不能直接當官方原文。
5. **正文完整性：** 不只是片段比對，應有可信獨立來源逐頁／完整文字對照；必要時進行人工驗收。若沒有獨立官方文字，應標記「PDF 可讀，但全文忠實性未驗證」，**不得冒稱 `full_text_verified=true`**。
6. **公開狀態與撤除：** PDF 真實可讀也不等於此後可持續公開，更新／撤除後的清除與備份處理需另行驗收。
7. **個資與日誌：** 正式系統須管控抽取過程的正文、OCR 中間檔、暫存、錯誤追蹤及備份；少年事件未公開文書不得納入測試。

**本輪 `pdf_fulltext_verified=0`、`all_formats_validated=false` 皆為固定阻擋，不會因長篇 HTML 通過而自動解除。**
