## 一、判定原則

本輪將「指定公開來源的研究樣本通過」「可進入下一輪個別功能審查」「允許正式合併、部署及提供法院個案資料」視為**三種不同的狀態**：

1. **指定樣本驗收通過**：只表示已保存的 GitHub Actions 證據，在當時所指定範圍符合測試標準；不能推論法規現今版本、裁判現時公開、函釋效力、歷審完整或未來 API 可用。
2. **候選功能可進入獨立審查**：法規、函釋等可以繼續規劃 UI、官方版本及來源標示，但**本輪不授權整合或部署**，先前通過的內容不必無故重做。
3. **正式發布／合併**：必須另有授權、現行來源、正確的正式功能測試、隱私／資安、資料保存／撤除與實際部署審查；**本輪全部維持未授權**。

任何使用者自行填入 `approved=true`、`full_text_verified=true`、`official_api_ready=true`、任意外部網址或模擬成功的案例，**都不能變更上述最後一項的阻擋狀態**。

## 三、本輪可執行的安全決策引擎

`experiments/v27-mcp-poc/stage3q-readiness-ledger.cjs` 提供不使用網路的三個入口：

- `featureStatus(id)`：依 immutable 的來源證據表返回每個功能的已確認層級、法遵限制、資料類型與不能執行的操作；
- `planReview({features})`：可將法規與函釋等列為「另行審查候選」，但只要要求裁判 HTML／歷審／PDF／公開狀態／確定／個別連結，即維持 release block；**永遠不返回允許合併部署、取得真實 Token、正式裁判全文或個別深連結**；
- `publicCourtPresentation({format})`：不使用使用者輸入的 JID、網址、摘要或 `verified:true`；只顯示安全狀態與**司法院裁判書系統通用入口** `https://judgment.judicial.gov.tw/FJUD/`。

**這不是可以直接放到正式網站的身分驗證後端。** 其 immutable 既有證據主要用於防止在後續規劃中誤寫「已驗收」或放行未經授權的服務；真正正式上線還需獨立的可信來源／配置／變更管理。此程式不驗證真正的即時法規、判決、API、法院來源或使用者身分。

`stage3q-review.html` 是**完全靜態、禁用 JavaScript／網路資料請求**的離線展示範例，可用電腦瀏覽器打開審查分級。它不是現有 v2.7 前端功能，也不會取得個案內容。

## 四、下一階段可採用的分線路線

### A 線｜目前可繼續規劃的內容（不是部署授權）

**優先完成法規及函釋的獨立介面驗收：**

- 每項法規必須註明官網來源、取得日期與修正／施行日；不能自動以歷史快照宣稱「現行法」。
- 函釋依官方真正公開程度區分 `full_text_verified`、`official_abstract_only`；站方摘要另標示；效力固定為「尚待查證」除非有可稽核的個案來源更新證據。
- 憲法及立法資料僅提供來源索引與已核對範圍，不得把抽樣範圍以外的全部理由書自動填為可信全文。
- 僅完成上述獨立測試、版本更新、資安與法遵審查後，才另行請使用者確認是否允許修改、合併或部署既有 v2.7。

### B 線｜裁判功能維持阻擋

- 公開 HTML 抽樣結果可以供工程研究及來源分析，但**不作公共個案全文、摘要或深連結發布**。
- PDF 在缺真實來源及同版獨立驗證之前，固定顯示「司法院可能提供 PDF；本站尚未核實全文，請自行至官方系統確認」。
- 正式個案檢索需要可信的當下仍公開確認、撤除與更新監控、快取／備份／日誌生命週期、未成年個資審查、後端資安及明確部署授權。官方七日前的 JList 不等於點擊時刻的官方確認。
- 裁判「是否確定」一律維持「尚待查證」，直到有獨立可靠證據；不得把歷審清單轉換成確定標記。
