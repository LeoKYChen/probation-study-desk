- 兩件均沒有下載 PDF，也沒有實際比較 PDF 正文。
- PDF 偵測及「僅有預覽／連結不得當作完整 HTML 正文」的**合成負面測試已通過**。
- `pdf_fulltext_verified=0`、`all_formats_validated=false`。
- 若將來需要真正支援 PDF，須先確認官方來源、PDF 檔案的可用性及使用規範，再進行一次受控的 PDF 文字擷取／頁碼完整性及可讀文字比對。不能現在就聲稱已支援。

## 四、安全及隱私邊界

- 所有裁判候選均來自既有固定版本的公開法院／年別／民刑事查詢；拒絕特定少年／家事敏感案號和專門法院識別碼。一般民刑事裁判仍可能提及未成年人，**未據此宣告逐案個資再利用合法**。
- 官方 HTTP 來源採限定路徑、`follow_redirects=False`、回應長度及逾時限制。不將 HTTP 200、PDF 連結或非完整正文當成足以驗收全文的證據。
- 驗收 JSON 僅保留測試群組、官方裁判日期、正文正規化長度、格式分類及驗證結果；不包含當事人、姓名、原始裁判正文、PDF、實際 JID 或個別 URL。
- **CI 執行日誌仍可能由上游 MCP／HTTP 函式庫輸出公開裁判 JID 或查詢網址**。這些並非未公開少年裁判，也非報告中的案件全文；但並不能說「整份 CI 日誌完全未涉及個案識別」。若未來處理真實非公開或受限制資料，必須先完成日誌封存／遮蔽及權限控管，不能直接沿用此研究流程。
- 官方需帳密的開放 API 沒有呼叫，沒有提交或要求 Secrets，也沒有儲存裁判內容、設置公開裁判 API、更新 Cloudflare 或正式部署。
- 本輪程式在 `experiments/v27-mcp-poc/` 及獨立 `.github/workflows/`，未修改 `main`、v2.5、`development/v2.7/`、`services/v2.7-judgment/`。

### 下一輪建議

**優先修訂抽樣策略，而非降低驗收標準：** 從官方已公開的具體長篇判決及不同版型範例挑選少量固定樣本，再進行完整文字核對。PDF 需另行釐清合法取得與文字／頁碼完整性驗證方式，若只能取得預覽則應長期標示「來源有 PDF，全文尚未核實」。

正式上線前，還須獨立處理裁判持續公開、撤除、全文更新、個資與日誌及備份保留；現階段網站只保留**司法院通用裁判書查詢入口**，不讓使用者把未核對內容誤認成確定、有效或仍公開的裁判。
