## 一、為何重新選固定樣本

第十二輪已在跨年份 HTML 樣本中取得 5 件文字一致，但 8 件限定搜尋的官方正文最長僅 7,805 字元，無法滿足 10,000 字元長篇驗收。本輪**不降低標準，也不重查先前已驗收的案件**，改從司法院官網實際可搜尋的民事判決頁面，固定六筆事先已存在的 JID。沒有自造裁判案號。

長篇門檻：官方 `#jud` 下有足量、可獨立抽取的裁判正文，**正規化後至少 10,000 字元**。先核對法院、案件類型、年度、字別、號數及裁判日期，全部符合後才使用既有固定 SHA `ef677ad63c3206fc211a083fad8b1d9ef5015222` 的 MCP 進行擷取一致性比對。

## 三、驗收範圍與執行限制

- GitHub Actions [#38869992254](https://github.com/LeoKYChen/probation-study-desk/actions/runs/38869992254) 執行成功，研究腳本離線合成安全測試及有界真實來源驗證均完成。
- **實際 5 次官方 HTTPS `data.aspx` 請求、2 次固定版本 MCP 裁判查詢**；沒有執行第六件。單次官方回應上限 1,500,000 bytes、無跨站轉址、無需額外官方 API 身分驗證。
- 未下載任何 PDF、未使用司法資料開放平臺 `Auth/JList/JDoc` 帳號或 Token、未查詢非公開少年裁判、未將正文與當事人內容寫入公開儲存庫或 CI JSON 產物。
- **注意：** 測試腳本必須包含六筆事先已公開的識別碼，第三方 MCP 亦可能於 GitHub Actions log 輸出公開 JID。不能因此宣稱「程式與全部日誌都沒有案號」。實質裁判全文與當事人內容不出現在驗收 JSON。
- 官方一般民事公開文書也可能含當事人姓名或其他個資；這次的技術擷取驗收不代表其可無限制散布、永久快取或用於模型訓練，也不是裁判是否涉及未成年人之法遵認證。

## 四、PDF 及其他格式仍是阻擋項

第十二輪實際偵測到兩件 `pdf_link_without_verifiable_html_body`，本輪並未下載、分析或比較該等 PDF。新分支另有 [Stage3m PDF 完整性及來源驗收規格](https://github.com/LeoKYChen/probation-study-desk/blob/experiment/v27-mcp-stage3m/experiments/v27-mcp-poc/STAGE3M.md)，要求合法官方來源、檔案及頁碼完整性、獨立案件身分、逐頁擷取／辨認與可靠全文對照；無法核對即 `review`。單有 PDF 連結、HTTP 200、OCR 片段或 PDF 可以打開都不能算全文忠實性通過。

- `pdf_fulltext_verified = 0`
- `all_formats_validated = false`
- `stage3_accepted = false`

本輪通過的兩件均為 `html_htmlcontent`，**不代表真實 `.text-pre`、`.jud_content`、僅 PDF 或長篇超大型附件已獲驗收**。

**優先做 PDF 來源與逐頁文字驗證的離線測試／小量合規評估**，但不直接爬取現有兩件 PDF-only 文書，也不以訓練 OCR 模型替代獨立真實全文驗收。須先確認官方合法取得方式、授權、資料不落地及可靠 PDF 原文檢驗管道；若欠缺這些條件，可直接將 PDF 類型長期固定為「官方來源存在，但全文尚未核對」，不阻礙其餘法規、函釋和一般 HTML 案件的獨立功能開發。
