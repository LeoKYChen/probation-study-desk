## 四、最重要的防錯機制

Stage3q 的 `featureStatus()`、`planReview()`、`publicCourtPresentation()` 具備以下行為：

1. 法規與函釋可顯示為**獨立審查候選**；只有來源研究分級可見，**不等於正式功能釋出**。
2. 裁判 HTML、歷審、PDF、即時公開、確定及個別連結，不能因為某筆先前資料抽樣通過就解鎖發布。
3. 使用者自行傳入 `approved=true`、`verified=true`、臨時來源證據或一般官網網址，**不能**使 `canMerge`、`canDeploy`、`canUseLiveApi`、`canStoreRealJudgments`、`canPublishIndividualCaseLinks` 為 true。
4. 提供裁判連結時僅能回傳司法院官方**通用**裁判書系統 `https://judgment.judicial.gov.tw/FJUD/`；不回傳個別 JID、由使用者供應的深連結、正文、摘要或 PDF。
5. 不存在的功能 ID、原型污染常見欄位名稱、任意 HTML 注入字串都拒絕，並且**不在錯誤輸出中回顯**。
6. 原有證據表為 immutable 只讀常數；不會因傳入仿冒欄位就改寫先前的驗收數目。
7. 不會因當下落在官方會員 API 夜間時間窗，就自動推定已有帳號或可以取用真實資料。

**已通過的安全測試不能代替可信後端的身分認證或正式發布控管。** 此工具是獨立研究決策檢查與展示範例，尚未連接實際 UI 或後端，不能視為已在正式站實際生效。

## 六、下一輪應如何有效率地推進？

### 建議優先：「法規及函釋的分層顯示」獨立驗收

不同於再次增加 PDF 合成測試，下一輪可用既有 **20／20 法規與 21 筆函釋**的來源證據，**只在獨立介面研究原型中**做三件真正可改善使用體驗的事：

1. 每筆法規標示所取得官方版本及時間，將「修正公布」與「實際施行」分別呈現；未知者清楚標記，不以歷史快照冒充今天有效的條文。
2. 每筆函釋的內容類型在畫面區分「官方全文已核對（17 件樣本）」「僅官方要旨已核對（4 件）」「站方人工摘要」，現行法律效力沒有權威證據時固定顯示「待查證」。
3. 憲法及立法抽樣成果只提供**來源層級與已查證範圍**，不擅自填補超出原資料支援的理由書、沿革及施行日期。

做完需另外執行 UI 整合、最新官方來源、資安及敏感資料測試，才由使用者審查是否可進下一步；**不默認允許正式上線**。

### 裁判類別維持現有安全策略

個案來源功能目前仍以**司法院通用查詢入口**為安全替代方案。PDF 「全文尚未核實」，裁判「是否確定尚待查證」，現時公開「沒有可信當下核實」。在正式授權、來源核對及撤除機制未建置前，不能將 Stage3 整體或裁判功能改為已通過。
