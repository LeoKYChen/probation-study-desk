# v2.7 × MCP｜第 3 階段第十四輪（Stage 3n）：PDF 安全讀取與逐頁比對原型

**獨立實驗分支：** `experiment/v27-mcp-stage3n`，以 `experiment/v27-mcp-stage3m` 為基礎。  
**定位：** 純離線**合成 PDF** 測試與安全閘門；**不是**能檢索、下載或驗證真實司法院 PDF 的正式功能。

## 一、與第十三輪的銜接

第十三輪已驗證兩件正規化正文長度達 16,297／15,217 字元的真實公開 HTML 長篇判決，完成該項文字擷取子測試；第十二輪另外曾在真實裁判網頁遇到 **2 件僅有 PDF 連結、而沒有可確認 HTML 正文**的來源。**這兩件 PDF 本輪不下載，也不執行 OCR**，其全文正確性維持 `review`。

本輪在不使用司法資料開放平臺帳號、官方 API、第三方 PDF 網址、真正裁判文書、當事人身分或非公開少年事件的前提下，先測試將來 PDF 接入前必備的防護規則。

## 二、程式組成

- `stage3n_pdf_gate.py`：採用 `pypdf==5.9.0`，只接收記憶體中的不可變 PDF bytes、合成來源假證據及逐頁合成預期文本。任何輸出只有狀態、錯誤分類及數量，不含 PDF 原文或案件文字。
- `test_stage3n_pdf_gate.py`：用 `reportlab==4.4.9` **全部在 RAM 中產生**不同的純合成 PDF，覆蓋 40 項測試。
- `.github/workflows/test-v27-mcp-stage3n.yml`：GitHub Actions 使用 Python 3.11 跑 40 項 PDF 測試，再用 Node 24 驗證既有 228 項合成裁判及服務安全回歸測試；只保存 JSON 測試件數與分項允許情形，**不附上 PDF**。

## 三、核心驗收規則

| 面向 | 防護及判定 |
| --- | --- |
| 輸入來源 | 必須是 `TEST_PDF_SYNTHETIC_...` 合成識別碼、列舉的合成法院、合法日期和明確的合成來源假證據；真實 JID 不進入本測試 |
| PDF 結構 | `%PDF-` 檔頭、EOF 訊號、檔案容量、加密狀態、頁數均須符合限制 |
| 防止過量 | 檔案最大 450 KB、最多 12 頁、單頁正規化最多 12,000 字元、整份累積最多 90,000 字元 |
| 互動風險 | 遇 `/Names`、`/AcroForm`、`/OpenAction`、`/AA`、頁面註記、嵌入檔等特徵則拒絕；這只是初步黑名單，非萬無一失的惡意 PDF 防護 |
| 可讀性 | **每一頁**文字過少（含空白頁、疑似影像掃描頁）即 `review`，不會自動 OCR |
| 文件身分 | 第一頁的合成案號、法院、日期、主文及理由必須為**精確行對應**，不可用前綴包含關係誤判 |
| 頁序及完整性 | 每一頁均需正確且唯一的 `PAGE:N/T` 逐頁標記；頁數及合成預期文字頁數必須相同 |
| 逐頁比對 | 只有所有頁面文字以 NFKC／去空白後**完整相等**，才得到 `synthetic_fidelity_passed` |
| 缺乏獨立參考文本 | 沒有逐頁參考、參考不足、任何一頁有差異或順序錯誤，一律不通過 |
| 真實官方驗收 | 無論合成測試是否通過，`real_official_pdf_fulltext_verified=false`、`individual_judgment_url_approved=false`、`stage3_accepted=false` |

## 四、使用方式

本輪僅是 Python 研究模組，**沒有任何網站端點、檔案上傳或下載按鈕**。

```bash
python -m pip install 'pypdf==5.9.0' 'reportlab==4.4.9'
cd experiments/v27-mcp-poc
python -m unittest -v test_stage3n_pdf_gate
```

程式產生的合成 PDF 不寫入磁碟；只在記憶體中生成及比較。測試例涵蓋：正常單頁與多頁、空白／不可讀頁、缺少或錯誤參考頁、日期／法院／合成案號錯配、頁碼標記錯誤、來源證據不合格、資料型態錯誤、破損 PDF、加密 PDF、嵌入附件、超限頁數／檔案／文字長度等。

## 五、實際限制：本階段「通過」不能支撐正式導入

1. **PDF 來源證據完全是注入的合成假資料**。資料類別或 `access_authorized=True` 是測試輸入，不是真實司法機關授權、有效 Token 或當下公開狀態。正式版必須在可信後端核查，不能信任使用者自行提供。
2. **合成預期頁文是測試夾具製造出來的答案**，不是另從司法院取得的權威獨立文本。未來若無可靠獨立原文，就算 PDF 正常讀取，也只能說「PDF 可讀」，不能說「全文逐頁與官方原文一致」。
3. **沒有擷取或 OCR 真實圖片掃描 PDF，也沒有視覺逐頁對照**。PDF 顯示的圖像文字與抽取的文字可能不一致，純文字擷取的測試不等同官方版面或頁數可靠性認證。
4. 雖限制 bytes、頁數及輸出長度，`pypdf` 本身仍有**解壓縮型資源耗盡或惡意結構風險**；本輪只靠 CI 執行逾時防護，並沒有為每個 PDF 建置獨立隔離程序、CPU／記憶體配額或抗沙箱逃逸審計，故**不能直接開放使用者上傳任意 PDF**。
5. 沒有驗證真實 PDF 的合法取得、來源檔案頁數完整性、數位簽章、雜湊與官方獨立同版原文，亦沒有實際檢查裁判撤除後的快取、備份或使用者已看過連結的後續處理。
6. 此模型將輸入 bytes 與擷取文字置於程序記憶體作短暫比對；「程式不自行寫入磁碟」**不代表整個執行環境的交換檔、第三方日誌或錯誤追蹤皆已完成個資管控**。真實個案仍不可投入此未驗收流程。

## 六、接下來應做什麼？

可再做**離線合成 PDF 的頁面視覺與文字層一致性負面測試**，特別確認文字層與可視內容不同時不能誤判通過；或者先就司法院真正的 PDF 取用方式、授權、逐頁獨立文字來源及刪除政策做法遵決策。

在正式證據管道尚未確認前，網站對 PDF 類型維持：**「來源有 PDF；全文尚未核實，請至司法院官方網站確認」**。沒有必要為此更動 v2.5、原 v2.7、`main`、Cloudflare 或已完成的 HTML／法規／函釋測試。
