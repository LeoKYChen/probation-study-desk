# v2.7 × MCP｜第 3 階段第十六輪（Stage 3p）司法院 PDF 來源、授權及撤除政策審查

**執行分支：** `experiment/v27-mcp-stage3p`，由 `experiment/v27-mcp-stage3o` 延伸。  
**本輪性質：** 官方規格與使用規範查核 + 純離線法遵／資料生命週期判斷原型。**不下載真實裁判 PDF、不登入會員、無 API 連線、不使用真實裁判全文或少年未公開事件，不動正式網站。**

## 一、官方依據及正確區別

### A. 《司法院裁判書開放 API 規格說明》（114 年 8 月 22 日版）

官方原文：<https://opendata.judicial.gov.tw/api/Newses/42/file>。

| 項目 | 官方規格所載資訊 | 本輪工程判斷 |
| --- | --- | --- |
| Auth | 使用司法院資料開放平臺之會員帳號／密碼取得有效期 6 小時的 Token | 尚未具備，也**不會**於程式庫或聊天取得帳密，不能測試 Auth |
| 使用時段 | API 每日 00:00–06:00 提供服務 | 不可拿會員 API 作為全天候當下公開狀態查核的唯一來源 |
| JList | 取得當日 **7 日前**的裁判異動 JID 清單 | 不是「此刻全部仍公開」清單，也不是已確定／歷審清單 |
| JDoc | 以 token + JID 取得裁判結構化資料，包含 `JFULLX`、`ATTACHMENTS` | 個案來源的身分、全文型態及文件角色須逐欄區分 |
| JFULLTYPE | `text` 或 `file` | `text` 不能被假裝成已核對真實 PDF |
| JFULLCONTENT | 官方欄位的全文文字內容；範例即使 `file` 仍可能含文字欄位 | 單靠此欄不得取代 PDF 逐頁文件內容比對 |
| JFULLPDF | `JFULLTYPE=file` 時提供全文檔案下載 URL | **主要裁判 PDF 的候選連結**，本輪只檢查文檔記載的路徑形狀，不實際下載 |
| ATTACHMENTS | 附件標題及各附件 URL | **附件不是主要裁判全文**；不可錯用作已驗收 `JFULLPDF` |
| 同一 JID 異動 | 相同 JID 重新取得內容，應依後取得的版本覆蓋舊版本 | 快取、檢索索引、衍生文字與使用者可見版本都須重新驗證 |
| 內容撤除／不再公開 | 官方特定「查無資料，可能未公開或已移除」訊息，要求刪除以前取得的裁判 | 須先停止提供舊全文；後端、備份、衍生資料與日誌的實際清除計畫另須驗證 |

**注意：** 官方 PDF 規格提供下載 URL 這件事，**不證明該 URL 可以無帳號、無時段或無其他取用限制直接 GET**。本輪沒有透過官方 API 查詢、取得或開啟任何裁判 PDF。

### B. 《司法院開放資料使用規範》

官方來源：<https://www.judicial.gov.tw/tw/communique/dl-115081-23e72637eb1d41f7b7606d097f3f0a52.html>，司法院 109 年 12 月 21 日函，110 年 1 月 11 日生效。

規範第二點區分：
- **一般開放資料**：任何使用者皆可取得；
- **會員開放資料**：僅供平臺註冊使用者取得。

規範第三點對平臺開放資料提供**無償且相當廣泛的加值使用權限**，原則上並非每次使用均須另外申請書面授權；但也要求衍生物清楚標示來源、不使人誤認由司法院製作。第四點要求遵守平臺下載／連線方式、維持資料正確、處理錯漏、尊重第三人權益，並依公告及異動通知維護會員開放資料。

**重要法律區分：** 「平臺開放資料原則上允許無償加值利用」不能解讀成「可以隨意繞過網站防護、免會員取得會員資料、收集不公開少年事件、永久保存撤除裁判或忽略個資」；反之，也**不能誤稱每一筆正式開放資料加值利用都另須司法院書面授權**。本輪所稱「專案管理者批准試辦、隱私審查、保存政策驗收」是我們為研究專案訂的**額外風險控制及執行條件**，不能冒充官方規範逐字規定。

### C. 官網「轉存 PDF」不等於獨立原始裁判全文

官方裁判書系統說明：<https://judgment.judicial.gov.tw/readme.aspx>，指出特定裁判網頁的「轉存 PDF」是網站產製具有頁行號的 PDF，並提醒資料僅供參考，如與判決原本不符，以判決原本為準。

故將「網頁轉存 PDF」拿來和**同一網頁**比較，只能測試同一來源的產製一致性，**不能視為彼此獨立的司法原始裁判證據**。如真正需要驗證官方 API 提供的 `JFULLPDF`，必須先合法取得且記錄其對應 JID、文件版本／公開狀態，再取得**可證明來源獨立性**的原文或同版參考。若沒有上述證據，應維持 `unverified`。

## 二、本輪新增的可執行離線閘門

程式：`experiments/v27-mcp-poc/stage3p-official-pdf-policy.cjs`。

### 來源角色分類

| 輸入類型 | 源自規格的區別 | 輸出分類 | 能直接下載／公布全文嗎？ |
| --- | --- | --- | --- |
| `jdoc_primary_file`，`JFULLTYPE=file` 且 URL 結構符合 `JDocFile` | JDoc 主全文檔案候選 | `documented_primary_pdf_url_shape` | **不能**，只檢查網址形狀，沒有真正的來源／授權證據 |
| `jdoc_attachment`，附件 URL 形狀符合 JAttFile／JFile | 裁判附件 | `attachment_only` | **不能作主全文** |
| `website_export_pdf` | 網頁產製檔案 | `generated_export_not_independent` | **不能當作獨立原文對照** |
| `jdoc_text` | JDoc 文字欄位 | `text_is_not_pdf` | **不得因此宣稱 PDF 逐頁完整** |
| 來源未核實、任意網址或可疑網域 | 不可信來源 | `source_not_established`／`blocked` | **不能** |

安全約束：HTTPS、精確的 `data.judicial.gov.tw` 網域、正確預期 API 路徑、不可含 URL 內帳密或 Token 查詢參數、不接受非 PDF 檔案、跨網域偽裝或編碼路徑穿越；所有分類只回傳理由和狀態，不複製輸入網址或案號。

### 來源試辦準入

`assessPilotReadiness()` 逐項檢查以下十三項**計畫層面的斷點**：

1. 平臺會員資格；2. 當前使用規範審查；3. 專案管理者另行同意小量試辦；
4. 官方來源身分；5. 查核當下仍公開；
6. 同版獨立全文參考；7. 同版獨立影像參考；
8. 個資／少年事件保護；9. PDF 解析沙箱；
10. 密鑰及加密傳輸；11. 已盤點資料保存副本；
12. 更新及撤除後的端到端清除驗收；13. 日誌與備份保存期限。

本輪即使把十三項**合成勾選值**全部設成 true，最多只能得到 `paper_requirements_only_real_evidence_still_required`。它不會登入、下載 PDF、啟用個案連結或合併部署。這些值不是真實證明，只是純離線政策測試。

若要以未來的官方會員 API 進行真正測試，程式還必須依臺灣時區判斷目前是否在每日 00:00–06:00 的服務窗口；時間範圍符合也不能取代會員身分及來源權限。

## 三、更新與撤除：官方義務與額外工程控制分開

官方規格要求**同 JID 新版本覆蓋舊版本、特定撤除訊息時刪除既有資料**。本輪的 `simulateLifecycle()` 只模擬，沒有持有真實裁判資料、也**沒有**真的刪檔。

工程自訂的副本盤點含：
`primary`、`cache`、`search_index`、`cdn`、`derived_text`、`exports`、`backups`、`logs`。

- **官方撤除事件：** 即刻停止個案全文／連結，將各副本列入待刪除或經法遵確認的保存／到期處理機制；只要有任一需處理副本缺乏實際完成證明，就保持 `purge_pending`。
- **同 JID 更新：** 停止提供舊版本，先完成舊版副本／衍生內容失效及新版本來源全文獨立查核，才可能另行恢復服務。
- **HTTP 403／404／逾時：** 不可直接宣稱已撤除；但也不得把上次快取當成目前仍公開。
- **備份與日誌：** 這些是工程安全盤點，不代表官方規格逐字要求「一律立即把所有法律依法應保存的安全日誌清除」。實際刪除、合法保存例外、加密與到期處理應經個資及紀錄保存政策審查。

所有「已刪除」輸入僅是假資料，`actualPurgeProven=false`、`caseCanBeServedAgain=false`、`stage3Accepted=false` 始終維持。不得把合成狀態記成實際履約已完成。

## 四、本輪的正式驗收範圍

這次只評估**規格可追溯性、資料角色區分、URL 防呆、會員及來源門檻、更新與撤除安全模型**。未驗收：

- 真實 `Auth/JList/JDoc` 登入及 Token 維護；
- `JDocFile` 或 `JAttFile` 真正的下載授權、回應內容、PDF 逐頁核對；
- 真實官方裁判更新／撤除事件是否能及時到達本站，真實副本能否全數清除；
- 獨立於來源 PDF 的官方文字及畫面比對材料；
- 24 小時可信公開狀態、全部歷審及裁判確定；
- 任何正式站點、上傳、下載、全文儲存及個案深連結功能。

因此 **`real_pdf_fulltext_verified=false`、`actual_purge_proven=false`、`stage3_accepted=false`**，在沒有新授權／來源證據以前應維持阻擋。

## 五、隔離確認及下一步

僅新增 `experiments/v27-mcp-poc/` 下的 Stage3p 程式、離線測試及說明，與獨立 `.github/workflows/test-v27-mcp-stage3p.yml`。不動 `main`、v2.5、`development/v2.7/`、`services/v2.7-judgment/`、Cloudflare，不使用付費服務或真實裁判內容。

下一步建議：先完成這輪驗收，**暫停額外的合成 PDF 規則堆疊**；接下來真正影響上線的是正式資料取得／公開性再驗證／更新撤除管理。若未來可完成合規取得途徑，才由專案管理者另行核准一件公開且允許測試的成人裁判，做最小量、隔離且不落地的真實驗證；否則 PDF 類型應長期只顯示「官方來源存在，全文未獨立核對，請至司法院查詢」。
