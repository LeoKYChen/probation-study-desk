## 一、經驗證的差異原因

兩件裁判均重新以獨立的 HTTP GET 取得官方 `judgment.judicial.gov.tw/FJUD/data.aspx`，另外透過固定上游版本 `ef677ad63c3206fc211a083fad8b1d9ef5015222` 的 MCP 取得相同 JID 的資料。

| 項目 | J01：114年度台抗字第2605號 | J03：114年度台抗字第2657號 |
| --- | ---: | ---: |
| MCP 回傳 `full_text`，NFKC + 移除空白後長度 | 2,288 | 1,286 |
| 官方整個 `#jud` 容器，採相同正規化後長度 | 2,288 | 1,286 |
| MCP 與官方整個 `#jud` 的正規化文字完全相同 | **是** | **是** |
| 官方 `#jud .htmlcontent` 正文長度 | 2,229 | 1,226 |
| 官方正文完整、連續地包含在 MCP 文字中 | **是** | **是** |
| MCP 在正文之前額外收錄的字元 | **59** | **60** |
| MCP 與官方正文的共同尾端字元 | **2,229／2,229** | **1,226／1,226** |
| 位於正文內的文字增刪區段 | **0** | **0** |
| 官方容器可識別的中繼資料列 | 4 | 4 |
| 本輪「文字擷取一致性」驗收 | passed | passed |

### 精確判讀

兩件裁判的差異均是 **MCP 在正文前多收了官方 HTML 容器內的頁首文字**，不是把裁判正文遺漏、改寫或截斷。本輪已用完全獨立的官方 HTML 擷取核對兩件正文，正文為相同的連續尾端，並且整個 `#jud` 容器的正規化文字與 MCP 回傳 `full_text` 完全一致。

**這不能推論未來所有裁判都是前綴 59／60 字元。** 不同法院、裁判種類、官方 HTML 版本可能有不同欄位或排版；未來的正文擷取須以可信的 HTML 正文節點定位，不能硬編碼 `full_text[59:]` 或 `full_text[60:]`。

## 三、重驗過程及安全要求

- 原本前輪 [#38846161540](https://github.com/LeoKYChen/probation-study-desk/actions/runs/38846161540) 用獨立官方「正文區塊」與 MCP 全容器文字比較，產生非逐字一致的 review；現在已證實差異位置與來源。
- 本輪 [#38846715253](https://github.com/LeoKYChen/probation-study-desk/actions/runs/38846715253) 使用 1 件官方網頁 GET + 1 件 MCP 取得／樣本，沒有大規模抓取。
- 只輸出中繼資訊、正規化長度、差異位置／長度、區塊識別與是否相同之布林值，**不寫入裁判正文、當事人、姓名、案情、HTML 或 PDF**。
- 測試包含負面情境：正文內文字一旦不同、來源被加上不明文字或網址不是官方指定頁面，不得誤判為完整文字一致。
- GitHub Actions 全部步驟成功，執行檔為 `experiments/v27-mcp-poc/stage3h_diff_diagnostics.py`，獨立工作流程為 `.github/workflows/test-v27-mcp-stage3h.yml`。

## 四、下一步：在固定來源的前提下擴到十件

現在**兩件樣本的內容擷取差異已釐清**，可規劃其餘 **8 件**成人公開裁判樣本的可再現驗證。但仍須：

1. 只能從**實際司法院公開檢索結果**取得真實識別碼，不得假造案號或使用不公開少年裁判。
2. 優先取得不同法院、案件類型及不同官方 HTML 版型，不可只用最高法院兩件樣本推論全國法院一致。
3. 每筆核對官方頁面身份、裁判日期、完整正文區塊與擷取忠實性；未能獨立取得官方正文就列 review。
4. 歷審資訊及撤除後續異動為**另外的分項驗收**；資料欠缺不得推定已確定、現在仍公開。
5. 在官方開放 API 的取得及服務限制未能解決前，維持「個別深連結暫不對外提供」，只保留官方裁判書系統通用入口。
