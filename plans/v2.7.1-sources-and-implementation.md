# v2.7.1｜函釋與公開裁判智慧檢索：資料來源、架構與驗收計畫

- 狀態：規劃待開發（不代表已取得API帳號、資料授權或已完成部署）
- 制定日期：2026-10-15
- 分支：`feature/v2.7-legal-search`
- 基礎：v2.7.0 雙模式介面、少年事件處理法120筆＋保安處分執行法103筆現行法規快照
- 產品定位：共用檢索核心、國考模式與專業研究模式；初期**不建置AI生成或自動引用裁判見解**。

## 一、官方資料來源及確定性

| 類型 | 官方入口或介面 | 已確認 | 限制與決策 |
|---|---|---|---|
| 行政函釋 | https://mojlaw.moj.gov.tw/lawquery.aspx | 可依類別、關鍵字、文號及期間查詢原文 | 尚未確認**全部行政函釋**可公開批次下載API；先索引人工核對的文書、原始網址與個別有開放授權的資料集；不得未確認授權即大量爬取 |
| 特定行政函釋開放資料集 | https://data.gov.tw/dataset/17116 | 法務部廉政署特定函釋資料集提供JSON及文號、日期、資料連結 | 不代表法務部全部函釋；每個來源逐一檢查授權及欄位 |
| 公開裁判書 | https://opendata.judicial.gov.tw/ | 裁判書開放API有 `Auth`、`JList`、`JDoc` | 需申請會員帳號、Token有效6小時、服務窗口臺灣時間00:00–06:00、僅提供7日前異動清單，且遇撤除須刪除 |
| 司法院開放資料使用規範 | https://legal.judicial.gov.tw/FLAW/dat02.aspx?lsid=FL095666 | 另有授權、來源揭露、變更及個資規則 | 不得省略 |
| 專業手冊及學術資料 | 各有權公開來源 | 可為補充研究資料 | 不得混作法院裁判或行政函釋，不得上傳未公開卷證或少年裁判 |

官方裁判API規格（114.08.22）：https://opendata.judicial.gov.tw/api/Newses/42/file

API對接欄位（以官方PDF規格為準）：
- `POST https://data.judicial.gov.tw/jdg/api/Auth`：body含 `user`、`password`，回傳 `Token`。
- `POST https://data.judicial.gov.tw/jdg/api/JList`：body含 `token`，回傳7日前異動日期及 `jid` 列表。
- `POST https://data.judicial.gov.tw/jdg/api/JDoc`：body含 `token`、`j`（`jid`），回傳 `JID`、`JYEAR`、`JCASE`、`JNO`、`JDATE`、`JTITLE`、`JFULLX` 及附件等。
- PDF或其他附件是獨立文件，不能未讀正文即當作已取得全文。
- 取得相同 jid 新內容 → 覆蓋；官方回覆撤除/不再公開 → 刪除正文、摘要、索引、向量、快取及所有對外入口；備份也需訂定刪除處理方式。

## 二、資料結構與統一檢索

三種來源以一致的搜尋卡片呈現，但保留法律性質，不混為一談。

### 共用欄位
`id`（來源+唯一識別碼）、`kind`（statute/interpretation/judgment）、`title`、`originAgency`、`sourceUrl`、`documentDate`、`lastCheckedAt`、`dataSourceVersion`、`visibility`、`status`、`licensePolicy`、`sourceHash`、`lastIndexedAt`、`topics`。

### 行政函釋專用
`issuingAgency`、`officialDocumentNo`、`issuedAt`、`summary`、`fullTextAvailability`、`relatedArticles`、`validityReview`、`supersededBy`、`reviewStatus`。

**不得將「官網尚可搜尋」推定為「目前有效」**；有效狀態須逐案核對或標示未確認。

### 裁判專用
`jid`（唯一鍵）、`court`、`caseYear`、`caseType`、`caseNo`、`judgmentDate`、`caseTitle`、`judgmentType`、`publicationStatus`、`lastSeenAt`、`fullTextType`、`originalJid`。

法律效力、裁判是否確定、是否後續變更及個案涵攝不得僅依案號推定；需依來源資料核對。

## 三、技術架構

```
法規 laws.json ──────────────────────────────┐
行政函釋（人工核對+授權開放資料） ─────────────┤
公開裁判（後端Auth→JList→JDoc，含撤除處理） ─┤
                                             ▼
                     資料分流/正規化/識別碼/內容驗證
                                             ▼
                    共用檢索服務（精確→關鍵字→語意）
                            │                │
                    國考學習模式        專業研究模式
```

- 前端：沿用 `development/v2.7/` Cloudflare Pages；法條搜尋功能不得倒退。
- 初期函釋試點：如授權允許，以小規模JSON加原文連結先測試欄位與搜尋；不要把來源不足誤當為全面涵蓋。
- 裁判試點：透過經授權的私有後端儲存及可刪除的索引（例如Cloudflare Worker+D1/R2，選型需先核對可用額度及資料使用規則），**禁止將裁判全文提交公開 Git儲存庫或打入不可撤除的前端靜態資產**。
- API憑證只放 GitHub Actions Secrets或Cloudflare後端Secrets；不可寫進網頁JS、公開repo、日誌或前端請求。
- 初期檢索：條號／發文字號／jid精確搜尋、中文全文與字詞同義詞。語意向量及AI問答列後期，不作v2.7.1首發必要條件。
- 語意摘要必須先人工驗收；只收錄索引標題時不得顯示如同已讀完整裁判之見解摘要。

## 四、裁判同步的必要排程與失敗控制

1. 取得合規帳號與API權限，先用人工測試及最少量 jid 進行通訊驗證。
2. 例如每日臺灣時間02:30（UTC前一天18:30）在官方00–06時段內同步。此為**系統設計值，不代表排程已建立**。
3. 驗證Auth有效 → 取得7日前異動清單 → 遍歷 jid → JDoc讀取、更新或撤除；寫入異動日與執行結果，採冪等處理。
4. 每次先處理撤除；失敗重試需控制次數、速率；漏跑或超過API能追溯日期者，標示索引不完整並啟動人工官方補數方案，不得默默宣稱最新。
5. 變更jid的內容需更新正文、索引、摘要與快取；撤除者所有公開服務應立即不可檢索，實作索引清除及備份清除政策。
6. 若資料同步已過期，研究介面必須顯示最後成功核對時間與警告；若不能維持撤除處理能力，暫停公開裁判全文服務。
7. 注意 GitHub Actions 的 schedule 僅在預設分支執行；若維持獨立功能分支，應另設預設分支排程／Cloudflare Cron Trigger，不能誤認開發分支YAML的cron已啟用。

## 五、雙模式輸出

- 國考學習：輸入考點 → 法條 → 相關公開函釋及裁判（若收錄） → 不同見解 → 申論架構及法律時點警示；考試練習的題目與批改獨立處理。
- 專業研究：輸入法律問題 → 精確來源 → 法規時點 → 函釋權限與有效性 → 公開裁判原文及見解比較 → 待核查事項。
- 法規、行政函釋、裁判、研究文章必須以不同類型標籤呈現，不得當成同一層級法律依據。
- **少年事件**：沒有公開的裁判不可假造或以工作上取得的案件資料補足；公開裁判的少年相關個資及引述仍應特別注意。

## 六、工作批次及驗收

| 批次 | 交付物 | 主要驗收 |
|---|---|---|
| A. 資料來源與授權審核 | 資料來源清冊、開放條款、抓取方式、版本/撤除政策 | 每個來源有官方網址與取得依據；未授權不抓取 |
| B. 函釋檢索試點 | 來源經核對的函釋示範索引及文號/機關/日期/關鍵字搜尋 | 原文、文號、日期逐筆可回查；有效性不明有警語 |
| C. 裁判API可行性驗證 | Auth/JList/JDoc最小私有接入程式、錯誤與撤除測試 | 無敏感憑證外洩；可重新下載及移除 |
| D. 安全儲存與同步 | 可刪除儲存/索引及定期執行、異動稽核紀錄 | 變更覆蓋，撤除不再被搜尋；失敗不假裝更新 |
| E. 雙模式介面與檢索品質 | 統一搜尋、資料來源篩選、法律時點警示、測試報告 | 手機正常、舊法條可用、精確識別碼搜尋成功 |

建議最小試點：至少20筆已核對行政函釋、20筆依法公開且經API授權取得的裁判（實際數量取決於來源權限與可得性）；不虛構假案號或函釋。測試資料另外使用合成識別碼並顯著標示「非真實來源」。

驗收門檻：已收錄識別碼精確搜尋100%；展示的來源真實性100%；撤除測試100%；不洩露憑證/非公開少年資料；法律見解原文對照可核查。對完整資料庫的召回率需先確定語料覆蓋範圍才可正式量測。

## 七、待決事項與權限

- 行政函釋全量資料介接與著作授權尚未確認：先小規模、不承諾完整同步。
- 裁判API尚未測試登入，也未取得使用者的司法院會員權限；不要求在對話貼密碼或Token。待需要時，由使用者親自將最小必要權限的憑證設入Secrets。
- Cloudflare D1/R2與API成本、撤除/備份策略、司法個資風險需完成試點後再決定。
- v2.7.1不包含歷史法規完整資料庫、全臺灣函釋、公開裁判全量回填，也不提供法律AI自動閱卷或具拘束力的法律意見。
- `main`、v2.5正式站與`probation-study30-test`不得因規劃文件變更而被部署或修改。
