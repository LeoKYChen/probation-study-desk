# 每日模擬題高品質產題與發布前檢核提示詞｜v1.0

> **定位：建議插入現行每日 21:00「晚間司法與觀護摘要」提示詞內的考試專區規則；只強化考題，不覆寫原本新聞研究、Markdown 輸出、Google Drive 備份及固定週輪替的其他指令。**
>
> 狀態：品質提示詞修訂草案，尚未替換正在運作的 ChatGPT 排程，也沒有修改 Apps Script 或正式網站。原 342 題預測題庫維持暫停。

## 一、產題約束（供直接加入既有提示詞）

### 【新增：每日模擬題品質閘門 v1.0】

你正在為**116 年司法特考三等觀護人**編製每日練習的 25 分申論題。請完整保留舊版提示詞中的新聞查核、專業研究、固定輪替科目、Google Drive 及 UTF-8 Markdown 輸出要求。**僅將以下規則優先套用於「## 觀護人考試專區」**，不應改動既有 Markdown 固定標題：

1. **科目正確、題源分開。** 先依 Asia/Taipei 星期選科（週一犯罪學、週二心理學、週三諮商與輔導、週四少年事件處理法、週五刑事訴訟法與保安處分執行法、週六刑法、週日跨科整合）。`輪替科目：` 一整行**只能填科目名稱**，不得混入「原試題出處」「本週輪替說明」「原卷 URL」及長句。週五不得拆成純刑訴或純保安處分而偏離固定考科；可在設問中合理側重其中一部分。週日跨科整合以單一清楚情境作主軸，不要硬湊全部七科。
2. **唯一的可直接作答題幹。** `### 題目設計` 下只出現**一份最終完成的模擬申論題**；必須具備足夠事實、獨立且明確設問，不用「將其深化為」「請你產生」「改編方向」「原題／改編題二選一」「上文」「見附件」等編輯指令當題目。案例涉及年齡、時間、程序階段、行為及人物時，要讓考生能判斷法律或理論問題；不足之處補合理、無偏見的必要事實，禁止編造真實案件資料。
3. **25 分可核對。** 題幹明確標「（25 分）」；有分項時，每個子題單獨標示分值，**加總恰好 25 分**；每一子題與配分相稱。單一題不宜同時考過多完全不相關的制度，或讓一個很小的分項要求涵蓋五種龐大理論。避免模糊的「試論一切相關法律問題」。
4. **法律、學理嚴格分層。** 法律題先核對全國法規資料庫及司法院／主管機關最新資訊，釐清行為時法、現行法、法律保留、管轄與程序階段；法律條號、構成要件、適用例外、憲法與 CRC 等文件的法律性質不可臆測。少年事件處理法與刑法、刑訴、保安處分執行法交錯時，明示個別適用前提，不得直接套用成年人制度。理論題使用標準學術名稱、提出者、核心主張、限制及少年個案涵攝，區分相關與因果，不逕作臨床診斷。**資料無法核實時保留待確認，不猜測或寫成已生效的法律。**
5. **考古題來源不可捏造。** 若已實際開啟官方原卷，`原試題出處：` 可記年度、考試、完整科目、題號、官方精確連結、原題考點及改編差異。若未核實，**僅填「原創模擬題；考古題出處待核對」**，不冒稱某年某題或官方標準解答；原始來源資訊只放在`原試題出處：`，不可塞進 `輪替科目：` 或 `### 題目設計`。
6. **架構可以幫助學習，但不能洩漏在題幹。** `### 核心爭點與複習方向`、`### 答題架構建議`、`### 理論與少年個案應用分析表` 及 `### 複習方向` 沿用現有欄位；答案或提示寫在各自章節，**不能插入題幹內**。理論與少年個案應用分析表保留原四欄：`理論／方法｜理論／方法說明｜核心概念｜少年個案應用`。
7. **控制品質，不灌水。** 設計一題能在國考 25 分時間比例內作答、難度接近三等觀護人申論／實例題的題目；題幹原則上簡明、事實完整，必要時可較長，但不能以冗長角色設定、專業名詞羅列或跨科堆疊取代精確爭點。優先命中該科的重要制度、鑑別概念及真實評分得分點。
8. **每天輸出前，先在內部完成雙向複核（不得把自查文字混入題目）：**
   - [ ] 固定輪替正確；`輪替科目：` 只有純科目。
   - [ ] 題幹完整，只有一個最終模擬題，不含創作指令、前稿、原題全文或答案。
   - [ ] 設問清楚，分項明確，配分加總 25；讀者不需依賴新聞區才可作答。
   - [ ] 法律前提與引用已查證或誠實標註待核對；理論名詞與適用對象正確。
   - [ ] `原試題出處：` 與已實際查閱的來源一致，未捏造考試年度／題號。
   - [ ] 不與近期使用的核心事實、同一考點改寫題嚴重重複（僅在能取得既有題目時確認，取得不到須明示「未能驗證去重」）。
   - [ ] 原本 Markdown 五個固定小標、四欄表、日期與完整 UTF-8 MD 都存在且可被 Apps Script 穩定擷取。
   - [ ] 核心爭點、答題架構、表格與最後「題目設計」互相對應，沒有答非所問。
9. **未過閘門先自行修正，不以半成品交付。** 自行重新寫好真正的模擬題幹並重作完整檢查，再輸出；不得宣稱「已查核／無重複」但未做相應檢查。若受限於官方來源無法核實，改為清楚標註的原創題，不得為補足來源而虛構資料。格式或必要事實確實仍不完整，應標示「待補正，不得自動發布」，避免同步時誤判為已通過。

## 二、同步／上線端應另外處理（非純提示詞可保證）

生成品質檢查與 Apps Script 匯入驗證是不同層次，建議新題至少具備以下發布前阻擋條件：

- Markdown 考試區固定標題、`輪替科目`、`原試題出處`、唯一 `### 題目設計` 正確解析；未過則保持舊題庫不變，記錄「未發布／原因」。
- 題目非空、有真正設問，無「將其深化為」等生成殘句；科目欄位在允許值內，不含換行及出處敘述。
- 25 分完整可讀，分項加總正確；沒有配分或不明確時標記待複核，不能聲稱通過國考驗收。
- 比對來源文件 ID／版本與相近題幹，防止同一文件拆出「原題／改編題」兩份重複；**不以不同題號就認定不是重複題**。
- 新題可另存新 ID，舊題修訂必須保持原 ID 及對應的作答快照；若可能改變題意，先顯示歷史版本與差異並由使用者決定，不可覆蓋已寫答案。
- 即使 Google Docs 或 GitHub 更新失敗，也不能清空、重建或刪掉既有 132 題、426 題、任何個人答題紀錄。
- 程式只能自動檢查形式品質；法律爭議與重大學理錯誤仍需來源核對，**不宣稱提示詞可以保證 100% 正確**。

## 三、第三階段追加需求：每週學習建議

在現有「進度管理」區塊新增**本週三項優先學習建議**；從已保存的七科診斷、弱點原因、申論自評及到期題目唯讀計算。建議顯示：科目／考點、為何優先、建議練哪道原題、完成條件。沒有自評資料時不虛構弱點；不建立新分數、雷達圖、熟悉度資料庫或自動改課表。此功能與每日題庫生成分開測試，上線需另行確認。

## 四、實施順序

1. 本檔及現有 132 題盤點表先作隔離版設計基線。
2. 先追加夜間摘要考試專區的品質提示詞；原本新聞與研究提示一字不刪；實測 3～7 天的穩定輸出。
3. 在獨立 Apps Script／QA 分支加入品質阻擋與去重，避免把未通過題目同步到正式 JSON；並保留正式同步的回復方案。
4. 分批修正原有疑義題（先 P0／P1），確認來源與題意後再更新原 ID 對應題目；已合格不重審。
5. 每週學習建議另開獨立 PR，不修改現有學習指標運算或排程。
