# P1｜iPhone／桌面實機備份驗收單（僅流程驗收，不提交私人資料）

> 本文件對應 Issue #91 與 Draft PR #92；已取得 P1 資料安全驗收授權，**未取得 PR 合併、正式發布或部署授權**。2026-10-24 的 iPhone 五項驗收僅涵蓋選題、作答等基本功能，**不含 JSON 備份還原**。

## 一、驗收前的安全提醒

- 僅使用平常使用的**既有網站**備份；先記下實際網址（至少區分 GitHub Pages 與 Cloudflare）、裝置、瀏覽器與日期。
- **不得清空網站資料、刪除作答、重設瀏覽器、卸載 App 或在有重要學習紀錄的瀏覽器上測試「清除」。**
- 不要把含有個人作答、AI 金鑰、公務或少年個案資料的 JSON 上傳到 GitHub Issue、公開 PR 或本測試流程。可只回報檔案有無、大小是否大於 0、成功／失敗。
- 一律先確認目前頁面已顯示最新存檔；尚在編輯的分頁及 `sessionStorage` 中資料**不保證**納入備份。

## 二、iPhone 第一步：非破壞性匯出

1. 在實際使用的網站開啟 `/study-desk/`。於「進度與資料保存」按 **匯出書桌 JSON**。
2. 到 iPhone「檔案」App／下載項目確認檔案存在、大小非 0；格式名稱應為書桌專用 JSON。**不要將下載動作等同於備份已妥善儲存**。
3. 同一個網址來源開啟 `/backup/`，先確認頁面列出的範圍、未存內容提醒，再按 **下載完整學習紀錄 JSON**。
4. 同樣確認第二份檔案存在且非空。若當天只用書桌、其他模組從未產生資料，第二份可只含少量模組，不能憑大小推測所有資料皆在檔案中。
5. 若也使用另外一個網域（GitHub Pages／Cloudflare），**在另一個網域重複以上步驟**；兩個網站的 `localStorage`／`IndexedDB` 不會自動合併。

請僅記錄：網站網域（可去識別化）、瀏覽器、書桌 JSON 有無＋大小（KB）、其他模組 JSON 有無＋大小（KB）、下載時是否遇到錯誤。不用提供任何 JSON 內容。

## 三、還原測試必須隔離

- **禁止直接把備份匯回仍含重要作答的原瀏覽器以「測試」。**
- 第一順位是在 CI 的合成資料／全新隔離瀏覽器中還原（已有 `verification/sync/local-browser.cjs`、`backup/test-browser.cjs`、`backup-boundary.test.mjs`）。
- 使用真人備份檔進行第二裝置的還原，必須由使用者自行操作並確認該裝置可以安全測試，且要先備份其原有資料；不對真實作答進行清除、覆寫或任何線上上傳。
- 自動驗收與個人裝置驗收應分別紀錄；CI 綠燈不等於使用者備份檔實際成功還原。

## 四、驗收回報欄位

| 檢核項目 | iPhone 結果 | 桌面結果 |
|---|---|---|
| 完整網站網址／瀏覽器類型已記錄 | 使用者說明「Google」，待區分 Chrome／Google App；實際網站 URL 未回報 | 待確認 |
| 書桌 JSON 下載成功，檔案非空 | ✅ 使用者回報成功（依本表前述「非空」檢查回覆；未提供大小或檔案內容） | 待確認 |
| 其他模組 JSON 下載成功，檔案非空 | ✅ 使用者回報成功（依本表前述「非空」檢查回覆；未提供大小或檔案內容） | 待確認 |
| 確認兩份 JSON 內容範圍不同 | 待確認 | 待確認 |
| 空環境／合成資料匯入後，原稿與不同版本保留 | 不要求直接在原裝置進行 | 依隔離測試記錄 |
| GitHub Pages／Cloudflare 紀錄依網域分別處理 | 待確認 | 待確認 |

## 四之一、2026-10-25 使用者回報（僅匯出）

- 使用者於確認兩份 JSON 是否成功且非空、以及所用瀏覽器的提問後回覆：**「成功，Google」**。
- 解讀範圍：兩份檔案匯出之檢核**使用者回報成功**；「Google」僅記為使用者原稱，可能指 Google Chrome 或 Google App，**尚未確認具體瀏覽器**。
- 尚無檔案大小／檔案內容／網址／部署版本的獨立驗證；**不能推論資料涵蓋全部模組，不能推論已能還原**。
- 不要求使用者分享私人 JSON；仍不得在有重要紀錄的原瀏覽器中做破壞性匯入／清除。
- 本次回報不是新一輪正式部署或 PR 合併授權。
