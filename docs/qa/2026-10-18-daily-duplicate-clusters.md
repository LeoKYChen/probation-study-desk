## 三、去重處理原則

1. **候選群組不等於可刪除。** 目前 132 題原 ID 全部保留；132 題、題序、日別、題源及其他學習紀錄格式不變，避免使舊答案查找不到。
2. **先核對真正內容。** 對每一群核對完整題幹、子題配分、案件事實、主要爭點、來源 MD／Drive ID、法律要件與是否為不同版本；原始資料不存在或無法回查時，明示「來源未查得」，暫不判決二者誰是原本。
3. **不直接更換題號。** 如果未來要實作「僅顯示主版本」，應另建 alias/group 關聯（例如原題 ID → canonical），在介面層做折疊或選擇，而非物理刪除或合併個人的 `localStorage` 作答記錄。是否隱藏必須先檢查收藏、作答與備份在舊版本上的可見性。
4. **上游去重才是長期解。** Apps Script 同步時用來源文件 ID、段落位置、內容指紋做冪等處理；同來源重跑不可再次產生不同的新 ID；只看 ID 不重複是不夠的。此處是方案，不代表同步程式已修改。
5. **法律品質另走查證。** 先不改大段法條解釋與評分架構；確定資料來源及法律版本後才做實質法規或學理修訂。
