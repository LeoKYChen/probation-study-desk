# 新聞分檔同步替換包（2026-11-02）

## 目前狀態與先決條件

這是供手動安裝的完整程式碼，尚未更新正式 Apps Script。測試使用本機模擬 GitHub API，並非真實 Google Drive／GitHub 同步驗收。

**目前先下載、備份即可。PR #121 尚須完成正式網站發布。正式網站分檔讀取程式上線並核對後，才可貼入本包並執行同步。** 不能只把分檔資料寫入仍使用舊版讀取程式的網站。貼入後既有時間觸發器會自動使用新程式，因此也不要提早安裝。

網站發布需包含 PR #121 的新聞讀取、file-compat、產生器、Service Worker、離線清單與 Cloudflare 資料發布檢查；GitHub 與 Cloudflare 實際使用的版本都須核對。既有瀏覽器可能還有舊快取，發布後先連網重新載入並確認新版本。

## 替換步驟（網站就緒後）

1. 將 Apps Script 現有 ReadingNewsSync.gs、OfflineBridge.gs 全文各另存一份備份。
2. 完整取代 OfflineBridge.gs 的內容，儲存；接著完整取代 ReadingNewsSync.gs 的內容並儲存。不要另建同名函式，也不要只貼在檔案尾端。
3. 沿用既有指令碼屬性、資料夾設定、權杖與兩個觸發器；不需重新部署網頁應用程式。
4. 執行 previewReadingNews。此函式只讀取與預覽，不寫入 GitHub；核對來源份數、可呈現文件數、失敗份數。若 status／失敗訊息異常，先處理來源。
5. 執行 syncReadingNews 一次。成功訊息應為「新聞全文與離線資料已更新並讀回核對」。如果內容相同，會核對並修復離線檔案。
6. 等網站資料發布完成，連網重載正式站，確認新聞筆數、最新日期、至少一則全文、既有每日題作答。
7. 執行 repairDailyOfflineBridge：預期顯示「全部離線資料已核對（含新聞分檔）」；若顯示寫入修復，等待再次發布。
8. 重新下載新版離線包，斷網開啟並測試新聞全文及題目。既有舊離線 ZIP 不會自動得到新增內容。
9. 下一次既有排程執行後，再到 Apps Script 執行項目確認 syncReadingNews 成功；手動成功不代表排程已驗收。

## 成功判讀及限制

- 新聞總量保護上限：8,000,000 bytes；每個 JSON 分檔不超過 1,000,000 bytes，沿用原本單篇 250,000 字元及來源 300 份限制。這些都是程式保護值，不是按月額度，也不是無限容量。
- ReadingNewsSync 會把索引、新聞 JSON 分檔、離線主檔和離線分檔放在同一次 Git 提交。舊分檔不自動刪除。
- OfflineBridge 會讀取同一個 Git 提交中的來源，核對新聞雜湊、筆數及重複 ID；補建缺少的離線 JS，修復錯誤內容。來源損壞或權限錯誤時停止，不當成可補建的缺檔。
- Git 分支在作業途中變動時會停止或拒絕提交，請重新執行，不要強制覆寫。
- 週報與舊版單一新聞 JSON 仍支援；每日題仍沿用至少 125 題的既有防呆。
- 不需要提供 Token 給 AI。指令碼屬性中的既有值照常保留。

## 發生錯誤時

保留完整執行訊息供檢查。遇到「寫入後核對不符」先檢查最新 Git 提交，避免盲目重跑。已轉成 schemaVersion 2 後，不能單獨還原舊版 ReadingNewsSync，因為舊版不會讀取分檔；需將相容程式與資料視為整組處理。既有 Apps Script 版本備份不等於資料已回復。
