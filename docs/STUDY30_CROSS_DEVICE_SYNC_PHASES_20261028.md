# 每日30分鐘｜分階段跨裝置同步（2026-10-28）

## 目標與原則
- 手機／iPad → 公司電腦 → 家中筆電，依最新**已承接的** JSON 版本接續作答。
- 有效內容優先、衝突保留、不得無聲刪除既有答案。
- 保留完整 JSON 匯出／匯入、離線練習與使用者資料控制權。
- 不將學習草稿、機關或少年個資提交到 GitHub；測試僅使用合成資料。

## 第一階段｜手動 JSON 合併安全性（本分支）
- 完整備份的同日期資料：空白版本不得阻擋有內容的申論草稿。
- 按欄位補齊速記、四格大綱、申論全文、自評與其他已保存欄位。
- 若有明確 `_sync.revision` 承接鏈，可接受後續編輯的主要版本。
- 未能判斷先後的同欄位實質差異保留原主要版本，並將備份版本保存到 `psd-unified-backup-conflicts-v1`。
- 累計計時採同次練習安全上限（不相加）；不同裝置各自獨立計時的情境必須人工查核。
- 同 origin 另一分頁修改後，舊分頁停止覆寫，提示使用者先匯出本頁再重新載入。
- `backup/test-study30-roundtrip.cjs` 回歸測試：空白／有效草稿、欄位合併、衝突保存、版本承接、重複匯入、計時與其他日期保留。

**限制：** 本階段針對「完整學習紀錄備份」頁面的匯入合併。每日30分鐘模組內建的獨立舊版匯入仍有同日期跳過行為，尚未改造。跨不同 origin（GitHub Pages／Cloudflare）不能自動存取對方 localStorage，仍需手動匯入。尚未提供 Google Drive 自動同步。

**上線門檻：** 除 Node 邏輯測試外，須實際驗證 Chrome、iOS Safari／PWA，完成「07:30手機→12:30電腦→20:00家用筆電→隔日手機」全程，並驗證離線切換、衝突還原、既有資料保留與快取升級。驗收前不合併正式分支。

## 第二階段｜統一匯入與衝突管理
- 讓模組內建的獨立匯入與完整備份共用同一套安全合併邏輯。
- 在網站中比對、選擇、復原同日衝突版本（不只下載 JSON）。
- 補強同日多題與獨立練習之資料模型；定義多次計時的識別與安全累加規則。
- 用既有匿名合成資料驗證升級與回復；不得把真實草稿當測試 fixture。

## 第三階段｜Google Drive 自動同步
- Google OAuth 最小權限，使用者自行選擇／授權專用資料夾或應用程式建立的檔案。
- 保留本機優先及手動 JSON 備份，登入、離線、授權過期時仍能練習。
- 設計 ETag／revision 條件寫入，先拉取後合併再上傳，避免最後寫入者無聲覆蓋。
- 顯示本機已保存、雲端已同步、待同步、衝突、登入過期等真實狀態。
- 存取權限限縮、OAuth token 不寫入 JSON、不可把學習答案公開分享。
- Google API 專案設定與使用者授權需另外完成，不能以目前 ChatGPT 的 Drive 連線取代網頁程式本身的 OAuth 授權。


## 第二階段實作紀錄（開發分支 `feature/study30-sync-stage2-20261028`）
- 每日30分鐘頁面的單模組舊備份與完整備份，均使用完整備份核心的 `plan/apply` 原則：預覽、合併、保護版本、寫入失敗回復。
- 移除會整份取代並刪除其他日期的「完整還原」入口；需要復原者，可從完整備份頁先選擇歷史版本。
- 完整備份頁提供每日30分鐘衝突版本的三欄比對（目前、原版本、匯入版），並提供有保護備份及二次確認的逐日復原；取代前的主要版本會回存衝突歷史。
- 同日同題多次申論：使用者可手動「保存本次申論為獨立版本」，再編輯新版本；復原舊版時，先將目前有內容的草稿另存版本。儲存在既有 `sessions[date].essayVersions`，不另建儲存鍵。
- 獨立版本以 ID 合併，互不覆蓋。單一每日30分鐘計時器仍以當日累計 `elapsed` 為準，匯入時不直接加總不同裝置時間；多個獨立計時工作階段的精準去重需另行設計。
- 離線 PWA 預先快取共用核心及新介面，避免離線時匯入功能因核心腳本缺失而失效。
- 回歸測試 `backup/test-study30-stage2.cjs` 納入 `npm test`，採合成資料驗證。

**發佈限制：** 階段二以草稿 PR 提交，需通過 GitHub Actions、完整瀏覽器測試以及 iOS Safari／PWA 實機測試後，才可合併或部署。Google Drive OAuth 與自動同步仍屬第三階段。
