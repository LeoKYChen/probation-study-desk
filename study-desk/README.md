# 備考書桌：本機版開發

2026-10-22：跨裝置自動同步依使用者指示暫緩。本版採瀏覽器本機保存、JSON手動移轉，不需帳號、Supabase、token或付費服務。正式發布由既有GitHub Pages及Cloudflare流程執行，結果以Actions為準。

## 目前可用的學習流程

1. 在「進度與資料保存」勾選考科、設定科目權重、時間預算與搭配複習題數。
2. 在手動選題區確認已學主題，或把題目主題對應到一堂函授。函授必須由本人確認對應且觀看完成，才會依此納入已學範圍；不推定已掌握。也可標記需補強主題。
3. 今日任務先接續未完成題目，再處理到期回想；新題兼顧考科平衡、間隔、弱點與近期是否練過。畫面顯示推薦理由與排除數量，備份保存規則版本及選題摘要。主要任務與額外複習不超過設定的預估時間。
4. 通勤短練習可接續完整作答；保存作答版本後，加入多份AI／人工評語，再核對、訂正及獨立回想。流程完成與掌握程度分開。
5. 下載Markdown筆記與JSON備份。換裝置時手動匯入；差異版本另外保留，不自動覆寫原稿。

## 函授與複習設定

書桌唯讀取同一網址的既有函授紀錄，不改寫堂次、觀看時間或原課表。回到書桌時會重新讀取進度；進度退回未完課或堂次被移除時，相應主題不再依該對應納入推薦，手動確認已學的主題則仍保留。

確認對應、更新函授進度或匯出書桌JSON時，保存可攜的進度快照。另一裝置沒有即時函授資料時可使用該快照，畫面明確標示可能較舊；損壞的即時紀錄不會被舊快照悄悄取代。讀取既有快照不冒充剛重新查得的進度。

三種回想間隔可設1至365天，依序為「尚不會、需提示、可獨立說明」。設定只用於之後的訂正與回想，不改動已存在的到期日期；每次回想保存當時採用的間隔。

## 題庫與舊紀錄

載入既有主題庫374題與相關考試52題，共426個既有題目ID。題源沿用原題庫標示，沒有於本次重新逐題查核。複合科目保留原名，不擅自拆分。尚無內建題目的科目可登錄自選題。

匯入舊紀錄先保留原始快照。在「我的筆記」展開快照後，可將可辨識的專業科目申論、v2.5答案／四格草稿及每日模擬作答整理為可接續筆記；對應評語一併保留並標記來源／日期不詳之處。未能辨識的舊版本與欄位仍保留在原始快照，不猜測其意義。舊題幹無法辨識時明確標示，不能假裝已核對。

轉換採固定來源識別及完成回條，同一快照重匯不重複整理，也不覆寫之後在書桌編輯的答案。不因匯入而設定已核對、已訂正或已掌握。這是接入書桌的流程，沒有把書桌修改自動寫回舊模組。

## 保存與使用界線

- IndexedDB交易保存紀錄及匯入差異，跨分頁同題變動另存分支。
- 無登入介面、雲端輪詢或私人資料上傳；殘留舊服務設定也不使用。
- 計畫時間為預估，並非自動監控實際讀書時間。只開題而未作答不計入各科實際練習數。
- 本頁使用ES modules、IndexedDB與Service Worker，不能直接雙擊`file://`使用。原站其他模組的ZIP模式另有其相容性範圍。
- 正式首頁側欄已新增書桌入口；不改動既有六張主卡片。WebKit及實體手機尚未完成本書桌的專項驗收，不能以Chromium測試代替。
- 書桌選題與推薦不列社會工作、國文、法學知識與英文；舊筆記仍保留可接續與備份。
- 四格備份操作等寬等高；清除學習紀錄需輸入確認，可先下載JSON，保留考科設定，不刪除舊模組原始資料。

## 本機查看與測試

在儲存庫根目錄啟動 `python3 -m http.server 8781`，開啟 `http://localhost:8781/study-desk/`。

```bash
npm --prefix verification/sync ci
npm --prefix verification/sync test
node backup/test.cjs
node lectures/test.cjs
node verification/unified-integration.cjs .
node verification/sync/node_modules/playwright/cli.js install --with-deps chromium
npm --prefix verification/sync run test:browser
```

目前瀏覽器測試涵蓋作答→評語→訂正、離線重開、JSON手動移轉、Markdown歷程、函授對應與完成度變動、可攜快照、自訂間隔、時間預算、舊筆記轉換與重匯去重、426題入口、手機尺寸無水平溢出，及沒有外部連線。

測試套件在隔離位置時可用`PSD_SYNC_TEST_MODULES`指定node_modules；`BROWSER_EXECUTABLE`可指定現有Chromium。舊`browser.cjs`僅保留作為歷史同步驗證，不是本機版驗收。`cloud-sync/supabase.js`與資料庫腳本不由本機頁面載入。

## 雙 AI 協作交接（第二階段）

1. 先作答並按「保存作答版本」，再按「送交雙 AI 交叉審查」。
2. 確認送出後開啟獨立 [雙 AI 工作臺](https://leokychen.github.io/multi-ai-review-desk/)；題幹、題源與指定作答版本透過目前兩個分頁之間的限定訊息傳入，不包含於連結 URL。
3. 在工作臺自行選兩家服務、填入 API 金鑰，完成六份意見與人工核定；點「回傳雙 AI 意見至學習平臺」並在原視窗確認。
4. 評語以新的「待查證」回饋追加至該答案版本，不修改原答案與舊回饋。工作臺自身仍用獨立 JSON 備份。

安全限制：只支援從 https://leokychen.github.io 的學習平臺連至該網址的工作臺；必須保持來源頁面開啟。外部模型呼叫需要網路與使用者自己的 API 金鑰，可能產生費用。絕不可傳送真實可識別少年個案資料、機密卷證或公務秘密。關閉分頁或瀏覽器阻擋彈出視窗時，可用原有的「複製 AI 批改提示詞」及手動回填方式，不會遺失原始紀錄。

## 第三階段：人工確認弱點 → 訂正 → 再次回想 → 選題參考

「作答與訂正」新增七類缺口分類（爭點／問題辨識、法規／理論知識、涵攝／實務應用、論證／方法、結構與表達、來源查證、其他）。必須先保存答案、由本人完成資料核對並撰寫具體訂正，才會形成一筆已確認的弱點；單純接收雙 AI 評語不會自動分類或當成答錯。既有舊訂正沒有分類者顯示為「其他」，不更改原始資料。

「我的筆記」提供最近 30 項弱點摘要，顯示考科、類別、具體缺口、回想日期與自評，點選可回到原題。完整資料保存在原有作答紀錄及 JSON／Markdown 備份。訂正時另可**主動勾選**「這個主題需要優先補強」，僅對有題庫主題鍵的題目生效，沿用原本 `weakTopics` 選題參考規則；自選題不自動建立可能衝突的主題鍵。已學範圍、科目權重、時間預算與到期回想仍是原有選題約束，AI 不能繞過。

本階段不進行自動法條查核、AI 錯誤自動抽取、客觀掌握度推斷，也不聲稱國考題源已經官方核對。測試：`node verification/study-desk-weakness.cjs`。
