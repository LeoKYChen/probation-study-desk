# v2.7.1c 第二輪｜裁判撤除與 D1 Time Travel 還原安全作業程序

> **尚未部署。** 此文件供純合成測試與未來安全審查使用，不是正式上線授權。本輪沒有建立Cloudflare遠端D1、沒有真實裁判或司法院API憑證，也沒有公開HTTP查詢服務。

## 核心危害與策略

依Cloudflare D1 Time Travel官方文件，還原會**原地覆寫**當前資料庫。刪除過的資料可能重新出現，儲存在**同一個D1**的撤除紀錄也可能消失。即使已執行當前資料庫SQL刪除，仍不能聲稱歷史備份被即時消除。

- 官方：https://developers.cloudflare.com/d1/reference/time-travel/
- D1批次交易：https://developers.cloudflare.com/d1/worker-api/d1-database/

**分離兩個儲存域（僅離線模擬）：**
1. `0001_private_metadata.sql`：裁判中繼資料、搜尋詞、摘要、向量參考及本地封鎖狀態。
2. `0002_separate_revocation_ledger.sql`：獨立撤除墓碑、操作稽核、僅允許凍結的服務狀態與遞增版本。

兩者未來應使用不同D1資料庫、不同備份/還原範圍和不同操作權限。**獨立撤除表本身亦可能被還原或篡改**；因此另需可信、儲存在這兩個D1之外的「最小可接受撤除紀錄版本」見證。現行測試以注入函式模擬，**尚未建立真實可信見證系統**，故禁止存入真實裁判。

## 任何資料庫還原的必要流程（規劃，尚未操作遠端）

1. **預設封鎖**：停止所有對外API和排程，保持`private-worker.mjs`對任何HTTP請求回傳404。不要先執行還原後才封鎖。
2. **確認可信見證**：確認獨立撤除紀錄可讀，且其版本**不低於外部可信見證**。若看不到見證、撤除表或該表版本倒退，直接中止。
3. **確立還原範圍**：僅可操作中繼資料D1；不可順帶還原撤除紀錄D1或外部見證。記錄負責人、還原前時間、原因及預定還原書籤；此測試不執行Wrangler遠端命令。
4. **凍結、同步**：用`reconcileAfterRestore()`先對獨立撤除庫留下freeze稽核，再列出撤除jid，逐筆封鎖中繼資料庫的對應讀取；清除主表、索引、摘要、向量參考並查驗目前資料表為空。
5. **外部副本檢查**：核對CDN/Worker Cache、全文儲存、備份與Time Travel的保留情況、R2、外部搜尋引擎與任何已派生的摘要；尚未能驗證者一律視為未完成撤除。
6. **稽核紀錄**：將還原及清理行為寫入獨立稽核庫，確認版本前進，更新外部可信版本見證。要審計的項目包含版本、負責者、執行結果、撤除數量；任何日誌不得記載裁判全文或帳密。
7. **解除凍結必須人工核准**：本輪並**沒有**任何解除凍結程式或公開服務端點；未來須在所有法遵、個資、備份、撤除要求確認後才能設計。

## 程式對應

| 檔案 | 作用 |
|---|---|
| `revocation-ledger.cjs` | 獨立撤除紀錄＋稽核事件，驗證外部最低版本 |
| `restore-guard.cjs` | 讀寫前查核撤除庫，備份還原後凍結與重新清理 |
| `private-worker.mjs` | HTTP一律404、排程一律拒絕；不連接任何真實資料 |
| `d1-metadata-adapter.cjs` | 純合成資料的SQLite/D1形狀介面 |
| `restore-guard.test.cjs` | 舊資料重現、撤除墓碑擋讀寫、版本倒退、資料庫不可用之測試 |

## 測試與範圍限制

```bash
node --test services/v2.7-judgment/*.test.cjs
```

- SQLite只在GitHub Actions記憶體內模擬兩個獨立D1綁定，沒有遠端Cloudflare管理權限。
- `revocation-ledger`未接入任何能防篡改的外部版本見證；人為同時還原撤除庫及外部見證仍可能失效。
- `ledger_audit`是只由測試模組新增的稽核事件紀錄，**不具不可竄改的密碼學證明**。
- 目前`publicLookup()`及Worker HTTP均封鎖，不表示將來配置正式Worker時能免除授權與滲透測試。
- **撤除後刪除當前資料≠所有歷史副本已銷毀**。正式裁判仍禁止匯入，直到有合規且可驗證的備份、撤除及復原政策。
